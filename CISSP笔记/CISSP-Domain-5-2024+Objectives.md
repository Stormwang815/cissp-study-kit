# [Domain-5](#domain-5-identity-and-access-management-iam) **身份和访问管理 (IAM)**

身份和访问管理 (IAM) 领域重点关注与授予和撤销访问数据或在系统上执行操作的权限相关的问题，约占考试的 13%

- 资产包括信息、系统、设备、设施和应用程序，组织使用物理和逻辑访问控制来保护它们
- **访问控制**：共同保护组织资产的机制集合，允许对授权主体进行受控访问，允许管理层指定哪些用户可以访问哪些资源以及他们可以执行哪些操作；提供个人问责制
- **访问控制原则**：需要知道、最小权限和职责分离
- **访问控制服务**：（又名 AAA 服务）识别、身份验证、授权和责任
- **身份验证**：通过将一个或多个身份验证因素与保存用户身份验证信息的数据库进行比较来验证主体的身份；主体通过提供身份验证凭据来证明其身份
- **身份验证器保证级别 (AAL)**：身份验证过程稳健性的衡量标准； AAL 级别从 AAL1（最不稳健）到 AAL3（最稳健）进行排名，并在 [NIST 800-63-3b](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.800-63b.pdf) 中进行了描述
  - AAL1（确保用户控制与其帐户绑定的身份验证器）：允许单因素或多因素身份验证，对身份验证器类型的要求不太严格
  - AAL2（高可信度）：需要MFA，并且必须能够抵抗重放攻击
  - AAL3（极高置信度）：需要基于硬件的 MFA，并要求验证者模拟和网络钓鱼防御
- **问责性**：在对主体进行身份验证后，系统根据已证明的身份授权对对象的访问；审计日志和审计追踪记录事件，包括执行操作的主体的身份；有效识别、认证和审计的结合提供了问责制；请注意，**访问控制原则**是问责制
- 三个主要的认证因素是知识认证（你知道的东西）、所有权认证（你拥有的东西）和特征认证（你是什么）；类型 4 和 5 通常被视为补充或上下文因素，而不是主要身份验证类型
  - 您知道的事情：Type 1 身份验证（密码、密码短语、PIN 等）
  - 您拥有的东西：2 类身份验证（ID、护照、智能卡、令牌、PC 上的 cookie 等）
  - 您的身份：Type 3 身份验证，包括生物识别（指纹、虹膜或视网膜扫描、面部几何形状等）
  - 您所在的位置：类型 4 身份验证（IP/MAC 地址）
  - 你所做的事情：Type 5 身份验证（签名、图案解锁）
- 单点登录 (SSO) 技术允许用户进行一次身份验证并访问网络或云中的任何资源，而无需再次进行身份验证
- **访问控制系统**：确保根据业务和安全要求对资产的访问进行授权和限制
- **访问控制令牌**：基于时间、日期、日期等参数，令牌定义对系统的访问有效性
- **ADFS**：身份访问解决方案，为客户端计算机（网络内部或外部）提供对受保护的面向 Internet 的应用程序或服务的无缝 SSO 访问，即使用户帐户和应用程序位于完全不同的网络或组织中
- **异步令牌**（通过所有权硬/软令牌进行身份验证）：涉及质询和响应；它们更复杂（而且昂贵），但也更安全（请参阅同步令牌）
- **缓存中毒**：向缓存添加非预期元素（例如网页）的内容；一旦中毒，合法的网络文档可以调用缓存的项目，激活恶意缓存
- **能力表**：列出分配给主体的权限并标识主体可以访问的对象
- **CAPTCHA**：区分计算机和人类的完全自动化公共图灵测试是一种安全措施，用于防止帐户创建自动化以及垃圾邮件和暴力密码解密攻击
- **CAS**：中央身份验证服务（SSO 实现）
- **内容相关的控制**：内容相关的访问控制在识别和身份验证之外添加了额外的标准：主体尝试访问的实际内容；组织的所有员工都可以访问 HR 数据库以查看其累积的病假时间和休假时间，但如果员工尝试访问 CIO 的 HR 记录的内容，访问将被拒绝
- **上下文相关的访问控制**：在授予访问权限之前应用附加上下文，其中时间作为常用上下文
- **交叉错误率 (CER)**：确定生物识别方法的准确性，是在给定系统和环境中给定传感器的错误接受率（FAR 或类型 2）等​​于错误拒绝率（FRR 或类型 1）的点；如果两种错误的潜在影响相同，则为最佳操作点
  - **较低的 CER 表示生物识别系统更准确**
- **跨站点请求伪造 (CSRF)**：（又名 XSRF）一种攻击，强制经过身份验证的用户向他们当前进行身份验证的 Web 应用程序提交请求；在 CSRF 攻击中，预期目标是 Web 应用程序本身；该攻击利用了 Web 应用程序对用户浏览器的信任，并通过欺骗经过身份验证的用户提交伪造的请求，攻击者可以使 Web 应用程序执行操作，就好像该操作是由合法用户发起的一样
- **FRR**：错误拒绝率（类型1）是错误地拒绝合法身份验证并因此拒绝访问的概率；以百分比表示
- **FAR**：错误接受率（类型 2）是错误地将所声称的身份验证为合法、在此基础上识别并授予访问权限的概率；以百分比表示
  - 请记住：1 类错误就像在自家前门被拒绝； 2 类错误就像让陌生人进来
- **道德墙**：使用行政、物理/逻辑控制来建立/实施信息、资产或工作职能的分离，以实现需要了解的界限或防止利益冲突情况；又名区隔化
- **控制粒度**：安全功能中可以配置或调整性能和敏感性的抽象或细节级别
- **IDaaS**：基于云的服务，将 IAM 功能代理到客户本地和/或云中的目标系统；指在基于云的环境中实施/集成身份服务；服务包括配置、管理、SSO、MFA、目录服务、本地和云端
- **识别**：主体声称或声称身份的过程；主体通过识别来声明身份
- **身份证明**：AKA 注册，确认某人身份的过程；收集/验证有关请求访问/凭证/特权以与该人建立关系的人的信息的过程；身份验证包括基于知识的身份验证和认知密码，其中向用户询问一系列只有他们自己知道的问题
- **基于知识的身份验证 (KBA)**：根据权威来源中记录的用户历史记录向用户询问一系列问题的过程；例如银行向客户询问一系列有关他们过去居住的地址以及当前汽车/抵押贷款付款金额的问题
- **存储卡**：通过所有权因素进行的身份验证通常使用磁条作为存储器，每次交易时都会从磁条中读取相同的数据
- **对象**：主体访问的事物，例如文件；用户是在执行某些操作或完成任务时访问对象的主体
- **密码身份验证**：最弱的身份验证形式，但密码策略通过强制实施复杂性和历史记录要求来帮助提高安全性
- **策略执行点 (PEP)**：接收身份验证请求的应用程序组件，充当看门人，将请求发送到 PDP；一旦 PDP 做出决定，PEP 就会执行该决定（批准/拒绝）
- **策略决策点 (PDP)**：根据预定义的规则对 PEP 发送的授权请求做出决策
- **自助身份管理**：最终用户（相关身份）可以自行启动或执行的身份管理生命周期要素（例如密码重置、更改质询问题等）
- **服务器端请求伪造 (SSRF)**：如果 API 在未验证用户提供的 URI 的情况下获取远程资源，则此漏洞可让攻击者利用该应用程序将精心设计的请求发送到意外目的地（无论防火墙/VPN 保护如何）
- **SESAME**：多供应商环境中的安全欧洲应用系统，Kerberos 的改进版本； SSO 协议（如 Kerberos），但具有支持对称和非对称加密的优点（因此解决了 Kerberos 的密钥分发问题）；它还会发出多张票据来减轻像 TOCTOU 这样的攻击
- **会话**：成功的用户识别、身份验证和授权过程所创建的结果；代表用户和系统之间的连接和交互
- [**身份七定律**](https://www.ipc.on.ca/en/media/1525/download?attachment)：
  - 1：用户控制和同意：身份系统仅应在用户同意的情况下透露用户身份信息
  - 2：限制用途的最小披露：身份系统应尽可能披露最少的识别信息
  - 3：正当各方：系统应仅向有正当需求的各方披露信息
  - 4：定向身份：强调对公共和私人标识符的需求，让个人控制自己的身份以及如何建立信任
  - 5：运营商和技术的多元化：身份系统应与商定的协议和统一的用户体验进行互操作
  - 6：人员集成：企业应在系统和用户之间建立非常可靠的通信，并定期测试保障措施
  - 7：跨上下文的一致体验：统一的身份系统应该保证用户简单、一致的体验，允许用户决定在什么上下文中使用什么身份
- **智能卡**：通过所有权因素进行身份验证，其中包含嵌入式集成电路 (IC) 芯片，该芯片会在每次交易时生成唯一的身份验证数据（请参阅存储卡）
- **分割响应攻击**：导致客户端下载不属于所请求网页的预期元素的内容的攻击，并将其存储在浏览器缓存中
- **主题**：访问被动对象的实体，例如用户
- **同步令牌**（通过所有权硬/软令牌进行身份验证）：令牌生成器和身份验证服务器每 30-60 秒生成相同的令牌或一次性密码（请参阅异步令牌）
- **模板**：某人独特生物识别特征的数字表示（即表示生物识别数据的单向数学函数）；模板可以用作“1:N”进行识别（其中用户的模板用于搜索用户的身份），或“1:1”进行验证（其中用户被识别并且模板用作验证用户的因素）
- **捕鲸攻击**：针对拥有大量资产、授权进行大笔资金电汇的高级官员/私人的网络钓鱼攻击
- **XSS**：跨站点脚本（XSS）本质上使用反射输入来欺骗用户的浏览器从受信任的站点执行不受信任的代码；这些攻击是一种注入，其中恶意脚本被注入到其他良性且受信任的网站中；当攻击者使用 Web 应用程序向不同的最终用户发送恶意代码（通常以浏览器端脚本的形式）时，就会发生 XSS 攻击；允许这些攻击成功的缺陷非常普遍，并且发生在 Web 应用程序在其生成的输出中使用用户输入而不对其进行验证或编码的任何地方
- **XST**：跨站点跟踪 (XST) 攻击涉及使用跨站点脚本 (XSS) 和 TRACE 或 TRACK HTTP 方法；这可能会让攻击者窃取用户的 cookie

## [5.1](#51-control-physical-and-logical-access-to-assets-osg-10-chpt-13) 控制对资产的物理和逻辑访问 (OSG-10 Chpt 13)

- 控制对资产的访问（资产是对组织有价值的任何东西）；有形资产是你可以触摸到的东西，无形资产是信息和数据等东西；控制对资产的访问是安全的中心主题
- 了解没有物理安全就没有安全：如果不控制物理环境，管理、技术和逻辑访问控制就不会有效
- 了解身份是新的边界
- 了解您拥有哪些资产以及如何保护它们
  - **物理安全控制**：例如周边安全和环境控制
    - 控制访问和环境
  - **逻辑访问控制**：根据所提供的身份与先前批准的身份相匹配的验证来授权或拒绝访问的自动化系统；用于保护对信息、系统、设备和应用程序的访问的技术控制
    - 包括身份验证、授权和权限
    - 权限有助于确保只有授权实体才能访问数据
    - 逻辑控制将对系统/网络上的配置设置的访问限制为仅经过授权的个人
    - 适用于本地和云
- 除了人员之外，资产还可以是信息、系统、设备、设施、应用程序或服务

- 5.1.1 信息
  - 组织的信息包括其所有数据，存储在简单文件（服务器、计算机和小型设备上）或数据库中

- 5.1.2 系统
  - 组织的系统包括提供一项或多项服务的任何系统；带有数据库的网络服务器是一个系统；分配给用户和系统帐户的权限控制系统访问

- 5.1.3 设备
  - 设备是指任何计算系统（例如路由器和交换机、智能手机、笔记本电脑和打印机）； BYOD 已被越来越多地采用，设备上存储的数据仍然是组织的资产

- 5.1.4 设施
  - 任何物理位置、建筑物、房间、综合体等；物理安全控制对于帮助保护设施很重要

- 5.1.5 应用
  - 应用程序提供对数据的访问；权限是限制对应用程序逻辑访问的简单方法

- 5.1.6 服务
  - 身份管理的重点是控制对任何资产（包括数据、系统和服务）的访问；服务包括广泛的流程功能，例如打印、最终用户支持、网络容量等；如上所述，访问控制对于保护这些服务非常重要

## [5.2](#52-design-identification-and-authentication-strategy-eg-people-devices-and-services-osg-10-chpt-13) 设计识别和身份验证策略（例如人员、设备和服务）(OSG-10 Chpt 13)

- **识别**：主体声称或声称身份的过程
- **身份验证**：通过知识、所有权或特征验证身份来验证主体的身份；将一个或多个因素与有效身份数据库（例如用户帐户）进行比较
  - 身份验证的核心原则是所有主体都必须具有唯一的身份
  - 身份识别和身份验证作为单个两步过程一起发生
  - 用户使用用户名来识别自己并使用密码进行身份验证（或证明其身份）

- 5.2.1 组和角色
  - **角色**：与组织内的工作职能相对应的一组权限，而不是一组用户；用户被分配一个角色，并被授予与该角色关联的权限
    - 另一种说法是角色以功能为中心，例如，帮助台分析师，级别 1，是定义可用的特定权限的特定角色
    - 基于角色的访问意味着创建具有特定权限的角色，然后将其分配给该角色或工作中的某人
  - **组**：组是用户的集合，管理员可以为组分配权限，而不是为单个用户分配权限；这使得管理大量用户变得更加容易
    - 组以用户为中心，关注该组用户的集体身份
  - 身份和访问管理是用于控制对关键资产的访问的流程和技术的集合；其目的是管理对信息、系统、设备和设施的访问
  - 身份管理（IdM）实施技术通常分为两类：
    - **集中访问控制**：意味着系统内的单个实体执行所有授权验证
      - 可能会造成单点故障
      - 小团队最初可以管理，并且可以扩展到更多用户
    - **分散访问控制**：（又名分布式访问控制）意味着位于整个系统中的多个实体执行身份验证
      - 需要更多的个人或团队来管理，并且管理可能分散在多个地点
      - 难以保持一致性
      - 对任何单个访问控制点所做的更改都需要在其他访问控制点上重复
  - 随着无处不在的移动计算和随时随地的访问（应用程序和数据），身份成为“新边界”

- 5.2.2 身份验证、授权和计费（AAA）（例如，多重身份验证（MFA）、无密码身份验证）
  - 四个关键的访问控制服务：身份识别（身份断言）、身份验证（身份验证）、授权（访问定义）、责任（操作责任）
    - 请注意，AAA 与身份验证、授权的原理相同，并且使用“会计”一词代替“责任”（但原理相同）
    - 请记住，您需要了解的身份验证的三个因素是知识、所有权和特征（见上文）
  - 访问控制系统中的两个重要安全要素是授权和责任
    - **授权**：主体根据已证明的身份被授予访问对象的权限；为已识别和经过身份验证的用户或进程定义的访问级别
    - **问责制又称访问控制原则**：记录和监控的正确识别、身份验证和授权；实施审计时，用户和其他主体可以对其行为负责；通过审计来维持各个主体的责任；日志记录用户活动，用户可以对其记录的操作负责；这鼓励良好的用户行为并遵守组织的安全策略；另请参阅域 2 及以上中的定义/插值
  - **审计**：跟踪主题和记录访问对象时的情况，在一个或多个审计日志中创建审计跟踪
  - 审计提供问责制
  - FIDO2 和 WebAuthn 是相关技术标准，可在互联网上实现防网络钓鱼、无密码身份验证
    - **FIDO2（Fast IDentity Online 2）**：由 FIDO 联盟开发的一个总体项目和一组规范，旨在用加密密钥替换密码
    - **WebAuthn（Web 身份验证）**：由万维网联盟 (W3C) 与 FIDO 合作开发的特定 Web API 标准，允许网站（称为“依赖方”）直接与用户的浏览器通信以执行安全身份验证
  - **单因素身份验证**：仅使用一种身份证明的任何身份验证
  - **双因素身份验证 (2FA)**：需要两个不同的身份证明
  - **多重身份验证 (MFA)**：使用两个或多个因素的任何身份验证
    - 多因素身份验证必须使用多种类型或因素，例如您知道的东西和您拥有的东西
    - 注意：要求用户输入密码和 PIN 不是多因素（两者都是您所知道的）
  - 二因素法：
    - **哈希消息身份验证代码 (HMAC)**：包括基于 HMAC 的一次性密码 (HOTP) 标准使用的哈希函数来创建一次性密码
    - **基于时间的一次性密码 (TOTP)**：与 HOTP 类似，但使用时间戳并在一定时间范围内（例如 30 或 60 秒）保持有效
      - 例如基于手机的身份验证器应用程序，您的手机模仿硬件 TOTP 令牌（与用户 ID/密码相结合被视为两因素或两步身份验证）
    - **电子邮件质询**：网站使用的流行方法，向用户发送带有 PIN 码的电子邮件
    - 短信服务 (SMS)：向用户发送带有 PIN 码的文本是另一种双因素方法；请注意，NIST SP 800-63B 指出了漏洞，并反对使用 SMS 作为联邦机构的双因素方法
  - **无密码身份验证**：一种无需输入密码即可验证用户身份的方法；使用生物识别、安全令牌或移动设备等替代验证形式
    - 这是一个重要的主题，因为密码使用（和误用）会带来许多安全问题
    - 无密码身份验证的优点包括：
      - 增加安全性
      - 提高了用户便利性
      - 降低网络钓鱼的风险：如果攻击者获得了密码，但无密码身份验证使攻击者访问关联设备变得更加困难（例如，如果无密码身份验证是通过移动设备进行的）
    - 无密码身份验证的缺点：
      - 对设备的依赖（例如，如果通过手机，则需要该设备才能访问）
      - 与可靠性和隐私相关的生物识别问题
      - 与额外硬件设备等相关的实施成本

- 5.2.3 会话管理
  - **会话管理**：对成功的用户识别、认证和授权过程创建的会话进行管理；会话管理通过关闭无人值守的会话来帮助防止未经授权的访问；开发人员通常使用Web框架来实现会话管理，允许开发人员确保会话在不活动一段时间后关闭
  - 会话管理对于与任何类型的身份验证系统一起使用以防止未经授权的访问都很重要
  - 会话终止策略：
    - 时间表限制：设置系统可用的时间
    - 登录限制：防止使用同一用户ID同时登录
    - 超时：会话在一定时间不活动后过期
    - 屏幕保护程序：在一段时间不活动后激活，需要重新验证
  - 会话终止和重新身份验证有助于防止或减轻会话劫持
  - 开放 Web 应用程序安全项目 (OWASP) 发布了“备忘单”，为应用程序开发人员提供具体建议

- 5.2.4 注册、证明和身份建立
  - 在组织内，新员工在招聘过程中用适当的文件证明自己的身份
    - 亲自身份证明包括护照、DL、出生证明等
  - 在线组织经常使用**基于知识的身份验证 (KBA)** 来验证新人的身份（例如，新客户创建新的银行/储蓄账户）
    - 示例问题包括过去购买的车辆、抵押贷款金额、以前的地址、DL 号码
    - 然后，他们查询权威信息（例如信用局或政府机构）以进行匹配
  - **认知密码**：在帐户创建过程中收集的安全问题，稍后用作身份验证问题（例如宠物的名称、第一辆车的颜色等）
    - 与认知密码相关的缺陷之一是，这些信息通常可以在社交媒体网站或一般互联网搜索上获得

- 5.2.5 联合身份管理（FIM）
  - 基于云的应用程序通常使用联合身份管理 (FIM) 系统（SSO 的一种形式）
  - 联合身份将一个系统中的用户身份与多个身份管理系统链接起来
  - FIM 允许多个组织加入联盟或团体，同意共享身份信息
    - 每个组织中的用户可以在自己的组织中登录一次，并且他们的凭据与联合身份匹配
    - 然后，用户可以使用此联合身份访问组内任何其他组织中的资源
    - 每个组织决定共享哪些资源
  - 用于实施联合身份管理系统的方法包括：
    - 安全断言标记语言 (SAML)
    - 开放认证
    - OpenID 连接 (OIDC)
  - 基于云的联合通常使用第三方服务来共享联合身份
  - 联合身份管理系统可以托管在本地、云端或两者的组合作为混合系统

- 5.2.6 凭证管理系统（例如密码库）
  - **凭证管理系统**：为用户名和密码提供存储空间
    - 这些系统可帮助开发人员轻松存储用户名/密码，并在用户重新访问网站时检索它们，从而使用户无需再次输入凭据即可自动登录网站
  - 万维网联盟 (W3C) 于 2019 年 1 月发布了 Credential Management Level 1 API 作为工作草案，许多浏览器已采用
  - 一些联合身份管理解决方案使用凭证管理 API，允许 Web 应用程序使用联合身份提供程序实施 SSO
    - 例如使用您的 Google 或 Facebook 帐户登录 Zoom
  - **密码库（又名密码管理器）**：用于存储和管理凭据的系统；凭证通常保存在受主密码或密钥保护的加密数据库中
    - 在现代生活中，我们需要访问许多不同的系统，并且在许多系统中重复使用一个（甚至几个）密码意味着如果攻击者推断出您的密码，他们就可以访问许多系统（以及您的大部分数据）
    - 密码管理器可以更轻松地为每个系统创建不同的强密码，而无需记住它们
    - 当然，缺点是如果您的主密码被泄露，攻击者将可以访问您的所有系统

- 5.2.7 单点登录 (SSO)
  - **单点登录 (SSO)**：一种集中式访问控制技术，允许主体在系统上进行一次身份验证并访问多个资源，而无需再次进行身份验证
  - 使用 SSO 的优点包括：
    - 减少用户需要记住的密码数量，并且他们不太可能写下密码
    - 通过减少帐户数量来简化管理
  - 缺点：
    - SSO 会造成**单点泄露** — 如果 SSO 凭证遭到泄露，所有链接的资源都会暴露（这就是为什么需要 MFA 获取 SSO 凭证很重要）
  - 在组织内，中央访问控制系统（例如目录服务）通常用于 SSO
    - **目录服务**：一个集中式数据库，包含有关主体和客体的信息，包括身份验证数据
    - 许多目录服务都基于轻量级目录访问协议 (LDAP)

- 5.2.8 准时制 (JIT)
  - 支持即时 (JIT) 配置的联合身份解决方案会自动创建两个实体之间的关系，以便新用户可以访问资源
  - JIT 配置在用户首次登录第三方网站时在第三方网站上创建用户帐户； JIT 减少了管理工作量
  - JIT 解决方案无需任何管理干预即可创建连接
  - JIT 系统通常使用 SAML 来交换所需数据

## [5.3](#53-federated-identity-with-a-third-party-service-osg-10-chpt-13) 与第三方服务的联合身份 (OSG-10 Chpt 13)

- 5.3.1 本地部署
  - 在纯粹的本地场景中，所有基础设施均在内部管理
    - IdP：通常是内部目录服务（例如 AD）
    - 联合身份管理可以在本地托管，通常为组织提供最大的控制权
  - 需要内部专业知识和资本投资

- 5.3.2 云
  - 基于云的应用程序使用联合身份管理 (FIM) 系统，这是 SSO 的一种形式
    - IdP：在纯云场景中，身份管理通过第三方 (IDaaS) 提供
    - 基于云的联合通常使用第三方服务来共享联合身份（例如，培训站点使用联合 SSO 系统），通常将用户的内部登录 ID 与联合身份进行匹配
  - 需要放弃一些直接控制并依赖第三方的正常运行时间和安全性

- 5.3.3 混合动力
  - 混合联合是基于云的解决方案和本地解决方案的组合
    - IdP：身份通常源自本地（例如 AD），云服务充当中央 IdP
  - 需要仔细集成，并且是管理最复杂的场景

## [5.4](#54-implement-and-manage-authorization-mechanisms-osg-10-chpt-14) 实施和管理授权机制 (OSG-10 Chpt 14)

- 授权确保在给定经过身份验证的身份的特权的情况下，所请求的活动或对象访问是可能的
  - 例如确保具有适当权限的用户可以访问资源
  - 常见的授权机制包括：
    - 隐含的否认
    - 访问控制列表
    - 访问控制矩阵
    - 能力表
    - 受限接口
    - 内容相关的控制
    - 上下文相关的控制

- 5.4.1 基于角色的访问控制（RBAC）
  - **基于角色的访问控制（RBAC）**：关键特征是角色或组的使用； RBAC 模型使用基于任务的角色，当管理员将其帐户放入角色或组时，用户将获得特权；将用户从角色中删除会删除通过角色成员身份授予的权限
  - 用户帐户不是直接分配给用户，而是放置在角色中，管理员为角色分配权限（通常由工作职能定义）
    - 如果用户帐户属于某个角色，则该用户拥有分配给该角色的所有权限
  - MS Windows 操作系统将此模型与组一起使用
  - RBAC模型可以根据组织的层次结构将用户分组为角色，它是一种非自由裁量的访问控制模型；中央权限访问决策可以使用RBAC模型
  - RBAC 允许以最小的管理开销向用户分配权限

- 5.4.2 基于规则的访问控制
  - **基于规则的访问控制**：使用一组规则、限制或过滤器来确定访问；关键特征是它将全球规则应用于所有主题
    - 例如防火墙访问控制列表使用一系列规则来定义允许哪些访问以及阻止哪些访问
  - 基于规则的访问控制模型中的规则有时称为限制或过滤器

- 5.4.3 强制访问控制（MAC）
  - **强制访问控制（MAC）**：要求系统本身根据组织的安全策略管理访问控制的访问控制
  - MAC 模型的一个关键特征是使用应用于主体和客体的标签；主体需要匹配标签才能访问对象
    - 例如绝密标签允许访问绝密文件
  - 当记录在表格中时，MAC 模型有时类似于格子（即攀爬玫瑰花框架），因此它被称为基于格子的模型
  - MAC 模型强制要求了解原则并支持分层环境、分区环境或两者的组合（混合环境）

- 5.4.4 自主访问控制（DAC）
  - **自主访问控制 (DAC)**：资产或系统所有者决定谁有权访问的访问控制模型
  - DAC 模型的一个关键特征是每个对象都有一个所有者，所有者可以授予或拒绝任何其他主体的访问权限
    - 例如您创建一个文件并且是所有者，并且可以授予该文件权限
  - 所有对象都有所有者，所有者可以修改权限
  - 每个对象都有一个定义权限的访问控制列表（例如读取和修改文件）
  - 所有其他模型都是非全权模型，管理员集中管理非全权控制
  - Windows中使用的新技术文件系统（NTFS），使用DAC模型
  - **非自主访问控制**：资产所有者以外的其他人决定访问权限

- 5.4.5 基于属性的访问控制（ABAC）
  - **基于属性的访问控制（ABAC）**：基于规则的访问模型的高级实现，基于属性应用规则；一种访问控制范例，其中通过将属性组合在一起的策略向用户授予访问权限
  - ABAC 模型的一个关键特征是它使用的规则可以包括有关用户、环境、用户操作和目标资源的多个属性
    - 这使得它比基于规则的访问控制模型更加灵活，后者将规则平等地应用于所有主题
    - 许多软件定义网络 (SDN) 使用 ABAC 模型
  - ABAC 允许管理员使用简单语言语句（例如“允许管理员使用移动设备访问 WAN”）在策略中创建规则
  - ABAC 使用 XACML（可扩展访问控制标记语言）定义基于属性的访问控制策略语言、体系结构和处理模型

- 5.4.6 基于风险的访问控制
  - **基于风险的访问控制**：评估环境和情况，并根据软件安全策略做出决策
    - 在评估风险后授予访问权限的模型；它可以根据多种因素控制访问，例如由 IP 地址确定的用户位置、用户是否使用 MFA 登录以及用户的设备
    - 高级模型使用机器学习，根据过去的活动对当前活动做出预测结论
    - 请注意，例如，可以使用基于风险的访问控制，通过评估环境和情况来阻止来自受感染 IoT 设备的恶意流量，并使用该信息来阻止被视为异常的流量

- 5.4.7 访问策略执行（例如策略决策点、策略执行点）
  - **访问策略实施**：在组织内实施访问控制策略以规范和管理访问
  - 策略决策点（PDP）：负责根据预定义的访问策略和规则做出访问控制决策的系统； PDP 评估访问请求
  - 策略执行点（PEP）：负责执行PDP做出的访问控制决策； PEP 充当看门人

## [5.5](#55-manage-the-identity-and-access-provisioning-lifecycle-osg-10-chpts-1314) 管理身份和访问配置生命周期 (OSG-10 Chpts 13,14)

- 5.5.1 账户访问审查（例如用户、系统、服务）
  - 管理员需要定期审查用户、系统和服务帐户，以确保它们符合安全策略并且没有过多的权限
  - 使用本地系统帐户作为应用程序服务帐户时要小心；虽然它允许应用程序在不创建特殊服务帐户的情况下运行，但它通常会授予应用程序比其需要更多的访问权限
  - 您可以使用脚本定期运行并检查未使用的帐户，并检查特权组成员身份，删除未经授权的帐户
  - 防范两个访问控制问题：
    - 权限过多：当用户拥有的权限多于分配的工作任务所规定的权限时，就会发生这种情况；这些特权应该被撤销
    - 蠕变特权（又名特权蠕变）：随着工作角色和分配的任务的变化，用户帐户随着时间的推移积累额外的特权

- 5.5.2 供应和取消供应（例如，登机/下机和转乘）
  - 身份和访问配置生命周期是指帐户的创建、管理和删除
    - 此生命周期很重要，因为如果没有正确定义和维护用户帐户，系统就无法建立准确的身份、执行身份验证、提供授权和跟踪责任
  - **特权访问管理 (PAM)**：身份和访问配置生命周期的关键组成部分； PAM 解决方案管理、监控和审核特权帐户访问，包括会话记录、凭证存储和即时特权访问等功能
  - 配置/入职
    - 配置确保帐户根据任务要求拥有适当的权限，并且员工获得所需的硬件；换句话说，包括从应用程序、系统和目录中创建、维护和删除用户对象
    - 正确的用户帐户创建或配置可确保人员在创建帐户时遵循特定程序
      - 新用户帐户创建又称为注册或注册
    - **自动配置**：信息提供给应用程序，然后应用程序通过预定义的规则创建帐户（根据角色分配给适当的组）
      - 自动配置系统一致地创建帐户
    - **工作流程配置**：通过已建立的工作流程（例如人力资源流程）进行的配置
    - 配置还包括向员工发放硬件、令牌、智能卡等
    - 向员工发放硬件时保留准确的记录非常重要
    - 配置后，组织可以跟进入职流程，包括：
      - 员工阅读并签署可接受的使用政策 (AUP)
      - 解释安全最佳实践（例如受感染的电子邮件）
      - 审查移动设备政策
      - 确保员工的计算机可以运行并且可以登录
      - 配置密码管理器
      - 解释如何访问帮助台
      - 展示如何访问、共享和保存资源
  - 取消配置/卸载
    - 取消配置流程会在员工离职时禁用或删除帐户，而离职流程则确保员工归还组织为其分配的所有硬件
    - 当员工离开组织或调到其他部门时，就会发生取消配置/离职
    - **帐户撤销**：删除帐户是最简单的取消配置方法
      - 员工的帐户通常首先被禁用
      - 然后主管可以审查用户的数据并确定是否需要任何信息
      - 注意：如果被解雇的员工在离职面谈后保留对用户帐户的访问权限，则破坏的风险非常高
    - 取消配置包括收集发放给员工的任何硬件，例如笔记本电脑、移动设备和身份验证令牌

- 5.5.3 角色定义和转换（例如，分配给新角色的人员）
  - 创建新的工作角色时，确定该角色中的人员所需的权限非常重要；这确保了新角色的员工不会拥有过多的特权
  - 员工职责可以以转移到不同角色或新创建的角色的形式发生变化
    - 对于新角色，定义角色以及该角色员工所需的权限非常重要
  - 需要根据权限定义角色和关联组

- 5.5.4 权限提升（例如，使用 sudo、审核其使用）
  - **权限提升**：指给予用户超出其应有权限的任何情况
  - 攻击者在利用单个系统后，使用权限提升技术来获得提升的权限；通常，他们首先尝试在被利用的系统上获得额外的权限
  - **水平权限提升**：为攻击者提供与第一个受感染用户类似的权限，但来自其他帐户
  - **垂直权限提升**：为攻击者提供明显更大的权限
    - 例如在破坏普通用户的帐户后，攻击者可以使用垂直权限升级技术来获得用户计算机上的管理员权限
    - 然后，攻击者可以使用水平权限提升技术来访问网络中的其他计算机
    - 整个网络中的这种横向特权升级又称为**横向移动**
  - 限制授予服务帐户的权限会降低某些权限升级攻击的成功率；这应该包括尽量减少 sudo 帐户的使用

- 5.5.5 服务账户管理
  - **服务帐户**：应用程序、服务、系统使用它与其他资源、服务或数据库进行交互，无需人工干预
    - 尽管这些帐户主要不是由人类用于身份验证，但这并不意味着它们可以被忽略；这些帐户以及这些帐户的安全性需要进行审查和管理
  - **服务帐户管理**：创建、配置、监控和维护服务帐户的过程
    - 确保服务帐户的安全，降低未经授权的访问或滥用的风险

## [5.6](#56-implement-authentication-systems-osg-10-chpt-14) 实施身份验证系统 (OSG-10 Chpt 14)

- 联合身份管理（FIM）：（又名联合访问），另见 5.2.5 中的定义；  一次性身份验证以访问多个系统，包括与其他组织相关的系统； FIM系统将一个系统中的用户身份与其他系统链接起来以实现SSO； FIM 系统通过第三方云服务或混合系统在本地实施（提供最大程度的控制）；使用您的 Microsoft 帐户向第三方 SaaS 进行身份验证是 FIM 的一个示例
  - FIM 信任关系包括：委托人/用户、身份提供商（拥有身份并执行身份验证的实体）和依赖方（又名服务提供商）
  - FIM 协议包括 SAML、WS-Federation、OpenID（身份验证）和 OAuth（授权）
  - 比较 FIM 与 SSO：用户使用 SSO 进行一次身份验证，以访问一个组织中的多个系统；由于多实体信任关系，用户使用 FIM 进行一次身份验证，以访问组织内部和外部的多个系统
- XML 在 Domain 8 中定义，但本质上可扩展标记语言是一组 HTML 扩展，提供网络环境中的数据存储和传输；经常用于将网页与数据库集成； XML 通常嵌入在构成网页元素的 HTML 文件中
  - XML 不仅仅描述如何显示数据，它还使用标签描述数据本身
- 安全断言标记语言 (SAML)
  - **安全断言标记语言 (SAML)**：一种基于 XML 的开放标准，通常用于在联合组织之间交换身份验证和授权 (AA) 信息
  - 经常用于集成云服务并提供进行身份验证和授权断言的能力
  - SAML 为浏览器访问提供 SSO 功能
  - 结构化信息标准促进组织 (OASIS) 维护它
  - SAML 2.0 是一个基于 XML 的开放标准
  - SAML 2.0 规范使用三个实体：
    - **主体或用户代理**：主体是尝试使用服务的用户
    - **服务提供商（SP）（或依赖方）**：为用户提供服务
    - **身份提供商（IdP）**：保存用户身份验证和授权信息的第三方
  - IdP 可以发送三种类型的 XML 消息（称为断言）：
    - **身份验证断言**：提供用户代理提供正确凭据的证据，识别身份识别方法，并识别用户代理登录的时间
    - **Authorization Assertion**：指示用户代理是否被授权访问所请求的服务；如果被拒绝，请包括原因
    - **属性断言**：属性可以是有关用户代理的任何信息
- OpenID Connect (OIDC) / 开放授权 (Oauth)
  - **OpenID 提供身份验证**
  - **OpenID Connect (OIDC)**：使用 OAuth 2.0 授权框架的身份验证层，由 OpenID 基金会（而非 IETF）维护； OIDC 提供身份验证和授权（通过使用 OAuth 框架）
    - OIDC 是一种基于 RESTful、JSON（JavaScript 对象表示法）的身份验证协议，与 OAuth 配合使用时可以提供身份验证和基本个人资料信息；使用 JSON Web 令牌 (JWT)（又名 ID 令牌）
  - OAuth 和 OIDC 与许多基于 Web 的应用程序一起使用，无需共享凭据即可共享信息
    - OAuth提供授权
    - OIDC 使用 OAuth 框架进行授权，并基于 OpenID 技术进行身份验证
  - **OAuth 2.0**：RFC 6749 中描述的开放授权框架（由互联网工程任务组 (IETF) 维护）
    - OAuth 通过 API 交换数据
    - OAuth 是使用最广泛的云服务授权和授权开放标准
    - 基于 OAuth 构建的最常见协议是 OpenID Connect (OIDC)； OpenID用于身份验证
    - OAuth 2.0 使第三方应用程序能够代表资源所有者（通过协调审批交互）或允许第三方应用程序代表自己获取访问权限，从而获得对 HTTP 服务的有限访问权限； OAuth 提供从其他服务访问资源的能力
    - OAuth 2.0 通常用于对应用程序的委托访问，例如一款自动从社交媒体应用程序中寻找新朋友的手机游戏可能会使用 OAuth 2.0
  - 相反，如果您使用社交媒体帐户登录新的手机游戏（而不是仅为游戏创建用户帐户），则该过程可能会使用 OIDC
- 克伯罗斯
  - **Kerberos 是组织内最常用的 SSO 方法**
  - **Kerberos 的主要目的是身份验证**
  - **Kerberos 使用对称加密和票证来证明身份并提供身份验证**
  - **Kerberos 依赖 NTP（网络时间协议）在服务器和客户端之间同步时间**
  - **Kerberos 使用端口 88 进行身份验证通信**，客户端通过该端口与 KDC 服务器进行通信，以便用户可以有效访问特权网络资源
  - Kerberos 是一种网络身份验证协议，广泛用于企业和专用网络，并在许多 LDAP 和目录服务解决方案（例如 Microsoft Active Directory）中找到
  - 它提供单点登录并使用加密技术来加强身份验证过程并保护登录凭据
  - 票证认证是一种利用第三方实体证明身份并提供认证的机制
  - Kerberos 是一个著名的票证系统
  - 用户验证并证明其身份后，Kerberos 使用经过验证的身份颁发票证，用户帐户在访问资源时出示这些票证
  - Kerberos 版本 5 依赖于使用高级加密标准 (AES) 对称加密协议的对称密钥加密（也称为秘密密钥加密）
  - Kerberos 使用端到端安全性为身份验证流量提供机密性和完整性，并有助于防止窃听和重放攻击
  - Kerberos 使用端口 88，通常是 UDP，但对于较大的票证也使用 TCP
  - 有关 Kerberos 攻击的概述，请参阅第 3.7.12 节
  - Kerberos 元素：
    - **密钥分发中心（KDC）**：提供认证服务的可信第三方
    - **Kerberos 身份验证服务器**：承载 KDC 的功能：
      - **票证授予服务（TGS）**：提供主体已通过 KDC 进行身份验证并有权请求票证以访问其他对象的证据
        - 完整票证授予服务的票证称为票证授予票证 ([TGT](https://learn.microsoft.com/en-us/windows/win32/secauthn/ticket-granting-tickets))；当客户端向 KDC 请求服务器的票证时，它会以身份验证器消息和票证（TGT）的形式提供凭据，票证授予服务使用其主密钥打开 TGT，提取该客户端的登录会话密钥，并使用登录会话密钥加密客户端的服务器会话密钥副本
        - TGT 是加密的，包括对称密钥、过期时间和用户的 IP 地址
        - 主体在请求访问对象的票证时提供 TGT
      - **认证服务（AS）**：验证或拒绝门票的真实性和及时性；通常称为 KDC
    - **票证（又名服务票证 (ST)）**：加密消息，提供主体有权访问客体的证据
    - **Kerberos 主体**：通常是用户，但可以是可以请求票证的任何实体
    - **Kerberos 领域**：由 Kerberos 统治的逻辑区域（例如域或网络）
  - Kerberos登录流程：
    1) 用户提供身份验证凭据（在客户端中输入用户名/密码）
    2) 生成客户端/TGS 密钥
        - 客户端使用 AES 加密用户名以传输到 KDC
        - KDC 根据已知凭据的数据库验证用户名
        - KDC 生成一个对称密钥，供客户端和 Kerberos 服务器使用
        - 它使用用户密码的哈希值对其进行加密
    3) TGT生成——KDC生成加密的带时间戳的TGT
    4) 生成客户端/服务器票据
        - 然后，KDC 将加密的对称密钥和加密的时间戳 TGT 传输给客户端
        - 客户端安装TGT以供使用直至过期
        - 客户端还使用用户密码的哈希值解密对称密钥
        - 注意：客户端的密码永远不会通过网络传输，但会经过验证
            - 服务器使用用户密码的哈希值加密对称密钥，并且只能使用用户密码的哈希值对其进行解密
    5) 用户访问请求的服务
  - 当客户端想要访问某个对象（如托管资源）时，它必须通过 Kerberos 服务器请求票证，步骤如下：
    - 客户端将其 TGT 发送回 KDC，并请求访问资源
    - KDC 验证 TGT 是否有效，并检查其访问控制矩阵以验证所请求资源的用户权限
    - KDC生成服务票据并将其发送给客户端
    - 客户端将票证发送到托管资源的服务器或服务
    - 托管资源的服务器或服务使用 KDC 验证票证的有效性
    - 一旦验证了身份和授权，Kerberos 活动就完成了
      - 然后服务器或服务主机打开与客户端的会话并开始通信或数据传输
- 远程身份验证拨入用户服务 (RADIUS) / 终端访问控制器访问控制系统增强版 (TACACS+)
  - 多种协议提供集中式身份验证、授权和计费服务；网络（或远程）访问系统使用 AAA 协议
  - **远程身份验证拨入用户服务 (RADIUS)**：集中远程访问连接的身份验证，例如 VPN 或拨号访问
    - 用户可以连接到任何网络访问服务器，然后该服务器将用户的凭据传递到 RADIUS 服务器以验证身份验证和授权并跟踪记帐
    - 在这种情况下，网络访问服务器是 RADIUS 客户端，RADIUS 服务器充当身份验证服务器
    - RADIUS服务器还为多个远程访问服务器提供AAA服务
    - RADIUS 默认使用用户数据报协议 (UDP)，仅加密密码交换
    - RFC 6614 定义了通过 TCP（端口 2083）使用传输层安全性 (TLS) 的 RADIUS
    - RADIUS 使用 UDP 端口 1812 发送 RADIUS 消息，使用 UDP 端口 1813 发送 RADIUS 计费消息
    - RADIUS 默认情况下仅加密密码交换
    - 可以使用 RADIUS/TLS 来加密整个会话
  - 思科开发了**终端访问控制访问控制系统增强版 (TACACS+)** 并将其作为开放标准发布
    - 提供了对早期版本和 RADIUS 的改进，它将身份验证、授权和记帐分离到单独的进程中，这些进程可以托管在三个不同的服务器上
    - 此外，TACACS+ 会像 RADIUS 那样加密所有身份验证信息，而不仅仅是密码
    - TACACS+使用TCP端口49，为数据包传输提供更高级别的可靠性
  - **Diameter AAA 协议**：一种先进的系统，旨在解决旧 RADIUS 协议的限制（直径是半径的两倍！）； Diameter 通过提供增强的安全性（使用 IPsec 或 TLS 而不是 MD5 散列）来改进 RADIUS，支持更广泛的属性集（适用于大型、复杂的网络），并且可以处理复杂的会话
    - Diameter基于RADIUS，改进了其很多弱点，但Diameter与RADIUS不兼容
    - Diameter 旨在在传输层使用 TCP 和流控制传输协议 (SCTP)，专门解决 RADIUS 中发现的可靠性问题
