# [Domain-7](#domain-7-security-operations) **安全操作**

安全运营是为了保护资产，包括日志记录和监控、安全配置和变更管理等核心概念；当您讨论这些主题时，请牢记应有的谨慎和尽职调查；域 7 的考试权重约为 13%

- **警报类型**：威慑、驱避和通知
- **允许/阻止列表**：允许或阻止的实体、为特定特权、服务、移动性、访问或识别（包括网络、IP、地理、硬件地址、文件/程序）提供（或阻止）的实体的注册；允许名单上的实体将被接受、批准和/或认可；已弃用 AKA 白名单/黑名单；系统还会提醒 IT 安全人员，访问尝试涉及的资源不在预先批准的列表中；还可以包含反恶意软件
- **备用站点**：如果主站点不可用，则用于承担系统或组织运营的应急或运营连续性 (COOP) 站点
- **审计跟踪**：通过将有关事件和事件的信息记录到一个或多个数据库或日志文件中而创建的记录；它们用于重建事件、提取有关事件的信息以及证明或反驳罪责；使用审计追踪是侦探安全控制的一种被动形式，审计追踪本质上是刑事起诉中的证据
- **备份**：文件或程序的副本以方便恢复
- **基线**：系统所有组件的总库存（例如硬件、软件、数据、管理控制、文档、用户说明）；基线类型包括枚举（清单列表，由系统编目、发现或枚举生成）、构建安全性（每个 CI 的最小安全控制集，见下文）、修改/更新/补丁基线（总系统基线的子集）或配置基线（应包括与每个 CI 关联的修订/版本标识符）
- **堡垒主机**：网络上专门设计和配置以抵御攻击的专用计算机；它通常放置在非军事区 (DMZ) 或暴露的网段中，其主要功能是充当内部网络和外部、可能不受信任的网络（如互联网）之间的网关； Bastion 主机的主要特征包括：
  - 强化安全性：最大限度地减少正在运行的服务和应用程序的数量，从而减少潜在的攻击面
  - 公开访问：暴露于互联网或不受信任的网络，作为外部用户的第一联系点
  - 日志记录和监控：包括广泛的日志记录和监控以检测可疑活动
  - 有限的网络访问：通常对内部网络的访问受到限制
- **裁剪**：从大池中选择记录进行进一步分析的两种主要方法之一，裁剪选择超过预定义阈值的记录；裁剪是一种非统计采样形式，仅记录超过阈值的事件（另请参阅采样）
- **计算机犯罪**：针对或直接涉及计算机的违法违规行为，分为六类：军事情报攻击、商业攻击、金融攻击、恐怖攻击、怨恨攻击、恐怖攻击
- **配置项（CI）**：指定用于配置管理并在配置管理过程中被视为单个实体的信息系统组件的聚合
- **网络取证**：出于调查目的收集、保留、分析数据，同时保持数据的完整性
- **中断**：导致系统在一段时间内无法运行的意外事件
- **DPI（深度数据包检查）**：防火墙和其他网络安全设备使用的一种方法，用于在数据包通过防火墙时检查数据包的数据部分（或有效负载）； DPI 超越了传统的数据包过滤，不仅检查标头信息（例如源/目标 IP 地址和端口号），还分析数据包内的内容以识别和响应安全威胁
- **出口监控**：监控组织边界外的信息流
- **权利**：指首次配置帐户时授予用户的权限
- **实体**：尝试使用或访问系统资源的任何形式的用户，包括硬件设备、软件守护程序、任务、处理线程或人员；例如端点设备是人类（或非人类）用户用来访问系统的实体；应受到访问控制和记账
- **事件**：网络或系统中可观察到的事件
- **黑客攻击**：黑客攻击受害者为破坏涉嫌攻击者的系统而采取的行动
- **启发式**：识别可接受活动模式的机器学习方法，以便识别与模式的偏差
- **事件**：潜在或实际危害信息系统 CIA 或系统处理、存储、传输信息的事件
- **指标**：技术工件或可观察到的事件表明攻击即将发生、当前正在进行或已经发生
- **妥协指标 (IoC)**：入侵、恶意软件或其他预定义的敌对或危险事件集已经或正在发生的信号
- **信息安全持续监控（ICSM）**：保持对信息安全、漏洞和威胁的持续认识，以支持组织风险管理决策；持续的监控足以确保安全控制的有效性
- **信息共享和分析中心 (ISAC)**：为分析关键网络和相关信息以更好地了解安全问题和相互依赖性以确保 CIA 安全而创建的实体或协作机构
- **日志**：系统上发生的操作/事件的记录
- **运动探测器类型**：波形运动探测器将超声波或微波信号传输到监控区域，观察从物体反射回来的信号的变化；红外热探测器观察异常的热模式；电容探测器基于电磁场工作
- **MTBF**：平均故障间隔时间是对第一次故障和任何后续故障之间的时间的估计
- **MTTF**：平均无故障时间是给定特定操作环境下设备的预期典型功能寿命
- **MTTR**：平均修复时间是在设备上执行修复所需的平均时间长度
- **Netflow**：包含所有网络通信的源、目的地和大小信息的数据，并作为正常活动定期保存；捕获有关通信各方的信息以及交换的数据量
- **前兆**：事件发出的信号表明情况可能发生变化，这可能会改变当前的威胁格局
- **回归测试**：测试系统以确定最近批准的修改是否改变了其性能，或者其他批准的功能是否引入了未经授权的行为
- **变更请求 (RFC)**：支持变更管理活动的拟议变更的文档
- **资源容量协议**：用于确保在恢复场景中提供适当的资源
- **根本原因分析**：基于原则的系统方法，用于识别与特定风险集或事件相关的根本原因
- **RTBH（远程触发黑洞）**：一种与防火墙和路由器结合使用的网络安全技术，通过在恶意或不需要的流量到达目标网络之前丢弃恶意或不需要的流量来减轻分布式拒绝服务 (DDoS) 攻击或不需要的流量； RTBH的工作原理是创建一条“黑洞路由”，发往特定IP地址的数据包会被网络设备丢弃或“丢弃”，从而有效隔离恶意流量
- **抽样**：从大池中选择记录进行进一步分析的两种主要方法之一，抽样使用统计技术来选择代表整个池的样本；抽样是一个数据提取过程，从大量数据中选择元素以构建有意义的整体表示或总结；统计抽样使用精确的数学函数从大量数据中提取有意义的信息（另请参阅裁剪）
- **SCCM**：System Center Configuration Manager 是一款 Microsoft 系统管理软件产品，能够管理大量计算机，提供远程控制、补丁管理、软件分发、操作系统部署以及硬件和软件库存
- **安全事件**：任何破坏组织安全的尝试或违反安全策略的行为都是安全事件
- **SWG（安全 Web 网关）**：一种安全解决方案，可以过滤和监控组织的互联网流量，确保用户可以安全地访问网络，同时阻止恶意站点、防止数据泄露并执行 Web 浏览策略；虽然它不是传统的防火墙，但它通过专门关注网络流量安全来补充防火墙功能
- **TCP Wrappers**：基于主机的网络访问控制系统，用于类 Unix 操作系统中，用于过滤网络服务的传入连接；允许管理员通过基于传入 TCP 连接控制访问来定义允许或拒绝哪些 IP 地址或主机名访问某些网络服务，例如 SSH、FTP 或 SMTP； TCP Wrappers 依赖于两个配置文件：/etc/hosts.allow 和 /etc/hosts.deny
- **可信计算基础 (TCB)**：架构内所有硬件、软件和固件组件的集合，专门负责构成可信基础的对象的安全性和隔离
  - TCB 是一个通常与安全内核和参考监视器相关的术语
  - 可信基础强制执行安全策略
  - 安全边界是将 TCB 与系统其余部分分开的假想边界； TCB 组件使用可信路径与非 TCB 组件进行通信
  - **参考监视器概念（RMC）**：TCB 的逻辑部分，用于在授予访问权限之前确认主体是否有权使用资源；基于三个原则：完全中介（所有访问都必须由参考监视器验证）、可验证性（可以分析和验证参考监视器的正确操作）和隔离（必须保护参考监视器免遭未经授权的修改或篡改）
  - 安全内核是实现参考监视器功能的 TCB 组件的集合
- **元组**：元组通常是指表示网络连接或数据包的特定属性的值的集合；这些值用于唯一地标识和管理网络流，作为防火墙中状态表或规则集的一部分；例如，5 元组是五个值的捆绑，用于标识特定连接或网络会话，其中可能包括源 IP 地址、源端口号、目标 IP 地址、目标端口号和正在使用的特定协议（例如 TCP UDP）
- **供应商管理系统 (VMS)**：协助管理和采购人员服务、硬件、软件以及其他产品和服务的软件
- **基于视图的访问控制**：访问控制允许数据库在逻辑上分为记录、字段或组等组件，从而对非授权用户隐藏敏感数据；管理员可以按用户类型设置视图，仅允许访问指定的视图

## [7.1](#71-understand-and-comply-with-investigations-osg-10-chpt-19) 了解并遵守调查 (OSG-10 Chpt 19)

- **调查**：正式调查和系统过程，涉及收集信息以确定安全事件或违规的原因
- 调查人员必须能够进行可靠的调查，并在法庭上站得住脚；确保现场安全是每次调查的重要组成部分
  - 确保现场安全可能包括以下任何/所有内容：
    - 封锁该地区或犯罪现场的通道
    - 拍摄现场图像
    - 记录证据
    - 确保证据（例如计算机、移动设备、便携式驱动器等）不被接触、篡改或销毁
  - 一般步骤：
    - 识别并保护现场
    - 保护证据以保持其完整性和监管链
    - 证据的鉴定和审查
    - 对最有说服力的证据进行完整的额外分析
    - 产生最终的调查结果报告
- **洛卡交换原则**：每当犯罪发生时，就会拿走一些东西，并留下一些东西
- 调查的目的是：
  - 找出事件的根本原因
  - 防止将来发生
  - 减轻事件对组织的影响
- 调查类型：
  - **行政**：针对政策违规行为的调查
  - **刑事**：由执法部门进行，此类调查试图确定是否有理由相信（排除合理怀疑）某人犯罪
    - 目标是收集可用于在法庭上定罪的证据
    - 安全专业人员的工作是保存证据，确保联系执法部门，并在必要时提供协助
  - **民事**：合同纠纷等事项的非刑事调查
    - 民事调查的目标是收集可用于支持法庭法律主张的证据，通常由迫在眉睫或正在进行的诉讼引发
    - 与刑事调查相比，民事调查的证据水平要低得多
  - **监管**：政府监管机构有理由相信某个组织不合规时发起的调查
    - 此类调查的范围差异很大，根据指控的严重程度，可能与其他三种类型的调查类似
    - 与刑事调查一样，保存证据并协助监管机构调查人员至关重要

- 7.1.1 证据收集和处理
  - 证据收集很复杂，应该由专业人士完成，如果处理不当可能会被法庭抛弃
  - 保存原始证据很重要；一旦发现事件，就应开始收集证据，并收集尽可能多的有关事件的信息；该证据可用于随后的法律诉讼或查明攻击者的身份；证据还可以帮助确定损害程度；由于发现可能发生在事件发生后，因此将日志文件保留一段合理的时间至关重要；日志文件和系统状态信息可以保留在适当位置或存档中
  - **国际计算机证据组织 (IOCE) 媒体、网络和软件分析六项原则**：
    - 所有一般取证和程序原则必须适用于数字证据收集
    - 扣押数字证据不应改变证据
    - 访问原始数字证据只能由经过培训的专业人员来完成
    - 所有与扣押、访问、存储或转移数字证据相关的活动都必须完整记录、保存并可供审查
    - 拥有数字证据的人应对针对该证据采取的所有行动负责
    - 任何负责扣押、访问、存储或传输数字证据的机构都有责任遵守这些原则
  - **数字证据科学工作组 (SWGDE) 制定了基于计算机的证据标准化恢复的原则**：
    - 法律体系的一致性
    - 使用共同语言
    - 耐用性
    - 跨越国际和国家边界的能力
    - 灌输对证据完整性的信心
    - 法证证据在个人、机构和国家层面的适用性
  - **ISO/IEC 27037：数字证据识别、收集、获取和保存指南**：数字证据处理的国际标准，分为四个阶段：
    - 鉴别
    - 收藏
    - 获得
    - 保存
  - 证据类型：
    - **主要证据**：
      - 最可靠并在试验中使用
      - 原始文件（例如法律合同），无副本或重复件
    - **次要证据**：
      - 不如主要证据有力和可靠（例如原件副本、证人口头证据等）
      - 如果主要证据可用，相同内容的次要证据无效
    - **最佳证据规则**：规定应在法庭上出示原始证据，而不是副本或其他次要证据
    - **环境证据**：此类证据基于推论，可以用来支持结论，但不能证明它
    - **佐证证据**：此类证据用于支持其他证据，可用于加强案件
    - **展示的证据**：可以是审判中使用的物体、图片、模型、展示物，以支持当事人试图证明的事实
    - **直接证据**：此类证据基于证人的观察或专家意见，可用于证明现有事实（有备用证据支持）
    - **传闻证据**：基于法庭外某人的陈述的证据类型，通常不予采信；规则规定，证人不能就其他人告诉他们的内容作证；法院已应用该规则，律师不得将系统日志引入证据，除非系统日志经过系统管理员的验证
    - **口头证据规则**：确定是否可以使用额外/附加证据来更改或解释书面合同，表明书面合同优先于与其相关的任何口头谈判或规定；该规则通常禁止引入与合同条款相矛盾或改变合同条款的口头（额外）证据
    - **真实证据**：此类证据包括可以带上法庭的物理对象，例如计算机、硬盘驱动器和其他存储设备；真正的证据必须由证人唯一识别或通过记录在案的监管链进行验证
  - 值得注意的是，应以法医学上合理的方式收集和处理证据，以确保其在法庭上可接受并避免任何法律问题
  - **监管链**：重点是控制证据——谁收集和处理什么证据、何时何地
    - 考虑建立监管链：
      - 标签
      - 包和
      - 携带证据
  - 没收证据的基本替代方案：
    - 拥有证据的人自愿交出证据
    - 传票用于迫使当事人交出证据
    - 执法人员在履行法律允许的职责时，并且有充分理由相信与犯罪活动有关，扣押了明显的证据
    - 搜查令用于没收证据而不给主体改变证据的机会
    - 执法人员在存在紧急情况时收集证据
  - 五个证据规则：五个证据特征提供了通过法律和其他审查的最佳机会：
    - **真实**：证据不是捏造或栽赃的，可以通过犯罪现场照片或存储的逐位副本来证明
    - **准确**：证据完整（未经修改）
    - **完整**：证据必须完整，所有部分都可用并共享，无论它们是否支持案件
    - **令人信服**：证据必须易于理解并传达完整性
    - **可采纳**：证据必须作为案件的一部分被接受；可接受的证据必须与案件中的争议事实相关，该事实必须对案件至关重要，并且证据必须是有效的或合法收集的

- 7.1.2 报告和文件
  - 每项调查都应产生一份最终报告，记录调查的目标、遵循的程序、收集的证据和最终结果
  - 准备正式文件为潜在的法律行动做好准备，甚至内部调查也可能成为雇佣纠纷的一部分
  - 提前确定一个单一联系人，作为您与执法部门的联络人，提供具有单一视角的联络人，从而有可能改善工作关系
  - 参与 FBI 的 InfraGard 计划

- 7.1.3 调查技术
  - 无论是应对犯罪或事件、组织政策违规、解决系统或网络问题等，数字取证方法都可以帮助寻找答案、解决问题，在某些情况下，还可以帮助成功起诉犯罪
  - 法医调查过程应包括以下内容：
    - 犯罪现场的识别和保护
    - 正确收集证据以保持其完整性和监管链
    - 检查所有证据
    - 对最有说服力的证据的进一步分析
    - 最终报告
  - 信息和证据来源：
    - 口头/书面陈述：犯罪目击者或可能掌握相关信息的人向警察、调查人员提供或作为法庭证词
    - 书面文件：支票、印刷合同、手写信件/便条
    - 计算机系统：组件、本地/便携式存储、内存等
    - 视频/音频：与安全调查相关的视频和音频证据可能包括照片、视频、录音和安全摄像机的监控录像
  - 进行分析时可以使用多种调查技术：
    - 媒体分析：检查硬盘驱动器上尽管没有索引但完好无损的位
    - 软件分析：重点关注应用程序和恶意软件，确定其工作原理以及其试图执行的操作，以进行归因

- 7.1.4 数字取证工具、策略和程序
  - 数字取证：对存储介质中的数据进行科学检查和分析，以便将这些信息用作调查的一部分，以确定事件的罪魁祸首或根本原因
  - **实时证据**：存储在正在运行的系统中的数据，例如随机存取存储器 (RAM)、高速缓存和缓冲区
  - 检查实时系统可以改变证据的状态
    - 诸如与键盘、鼠标交互、加载/卸载程序，或者当然关闭系统电源之类的小变化，可以改变或消除现场证据
  - 每当对存储驱动器进行取证调查时，应首先创建原始驱动器的两个相同的逐位副本
  - **电子取证（E-Discovery）**：为法律诉讼识别、收集和生成电子存储信息的过程；电子发现参考模型 (EDRM) 有 9 个步骤：
    1）信息治理——确保信息组织良好，平衡价值、风险和成本
    2) 识别——定位发现请求所涵盖的电子存储信息的潜在来源，并确定其范围、广度和深度
    3) 保存——确保数据免受更改或破坏
    4) 收集——收集数据以供流程中进一步使用
    5) 处理——筛选和减少数据量，并酌情转换为适合审查和分析的形式
    6) 审查——评估数据的相关性；需要提供哪些信息以及可能需要保护哪些信息
    7) 分析 - 评估数据的内容和背景
    8) 生产——以可共享的形式提供电子存储的信息
    9) 演示——在适当的观众面前展示（例如证词、听证会、审判等）
    - 认为自己将成为诉讼目标的组织有责任保存数字证据

- 7.1.5 工件（例如数据、计算机、网络、移动设备）
  - 取证工件：系统或网络违规/企图违规的残留物，可能与调查或响应相关，也可能无关
  - 文物可以在很多地方找到，包括：
    - 计算机系统
    - 网络浏览器
    - 移动设备
    - 硬盘、闪存驱动器

## [7.2](#72-conduct-logging-and-monitoring-activities-osg-10-chpts-1721) 进行日志记录和监控活动 (OSG-10 Chpts 17,21)

- 7.2.1 入侵检测和防御系统（IDPS）
  - **入侵**：一个安全事件，或者多个安全事件的组合构成事件；当攻击者试图绕过或可以绕过/阻止安全机制并在没有权限的情况下访问组织的资源时，就会发生这种情况
  - **入侵检测**：一种特定形式的监控事件，通常是实时的，以检测表明潜在事件或入侵的异常活动
  - **入侵检测系统 (IDS)**：（又名防盗警报）是一种安全服务，用于监视和分析网络或系统事件，以查找/提供未经授权尝试访问系统资源的实时/近期警告；自动检查日志和实时系统事件以检测入侵尝试和系统故障
    - IDS 旨在作为纵深防御安全计划的一部分
  - **入侵防御系统 (IPS)**：IPS 是一种安全服务，它使用可用信息来确定攻击是否正在进行、发出警报并阻止攻击到达预期目标；包括检测功能，您还会看到它们被称为入侵检测和预防系统（IDPS）
    - IPS 可以是基于签名的检测系统，它将流量模式与已知攻击签名的数据库进行匹配；它可以是异常或基于行为的检测，从基线开始，将活动与基线进行比较以检测异常活动； IPS 也可以是基于策略的，将活动与预定义的安全策略或这些策略的混合进行比较
  - [NIST SP 800-94](https://csrc.nist.gov/pubs/sp/800/94/final) 入侵检测和预防系统指南提供了 IDS 和 IPS 的全面（尽管过时）覆盖

- 7.2.2 安全信息和事件管理（SIEM）
  - 安全信息和事件管理 (SIEM)：从多个来源获取日志、编译和分析日志条目并报告相关信息的系统
    - SIEM 系统很复杂，需要专业知识来安装和调整
    - 需要一支经过适当培训的团队，了解如何阅读和解释信息，以及在发出合法警报时要遵循的升级程序
    - SIEM 系统代表技术、流程和人员，每一个对于整体效率都很重要
    - SIEM 包含重要的智能功能，允许快速记录大量事件并对其进行分析和关联
  - SIEM 解决方案增强威胁检测和事件响应，提供可见性和合规性管理，并通过人工智能和自动化提高安全团队的效率
  - 主要能力包括：
    - 聚合
    - 正常化
    - 相关性
    - 安全存储
    - 分析
    - 报告
  - **安全编排、自动化和响应（SOAR）**：指一组允许组织自动响应某些事件的技术； SOAR 技术可自动响应事件；主要好处是，这减少了管理员的工作量，并且通过计算机/系统响应消除/减少了人为错误的可能性
  - **剧本**：定义如何响应事件的文档或清单
  - **Runbook**：剧本记录流程的实施；实现剧本的内容，将步骤转化为自动化操作
  - SOAR 允许安全管理员定义这些事件和响应，通常使用剧本和运行手册
  - SOAR 和 SIEM 平台都可以帮助检测并在 SOAR 的情况下响应针对软件开发工作的威胁
    - 开发人员可以抵制任何减慢开发过程的事情，这就是 DevSecOps 可以帮助建立正确的文化并平衡开发人员和安全的需求的地方

- 7.2.3 持续监控和调整
  - 有效的持续监控涵盖技术、流程和人员
    - 持续监测步骤为：
      - 定义
      - 建立
      - 实施
      - 分析/报告
      - 回应
      - 审查/更新
  - **监控**：查看信息日志、寻找特定内容的过程
    - 检测主体的恶意行为以及企图入侵和系统故障所必需的
    - 可以帮助重建事件、为起诉提供证据并创建分析报告
    - 持续监控可确保记录所有事件并在必要时进行调查
    - 监控是一种审计形式，重点是主动审查日志文件数据；它用于让主体对其行为负责并检测异常或恶意活动
    - 它还用于衡量系统性能
    - IDS 和 SIEM 等工具可自动执行连续监控并提供事件的实时分析，包括监控入口和出口网络流量
  - **日志分析**：一种详细且系统的监控形式，可分析记录的信息的趋势和模式以及异常、未经授权、非法和违反政策的活动
    - 日志分析不一定是针对事件的响应，而是一项周期性任务
  - SIEM 设置、配置、调整和运行后，必须定期更新并持续监控才能有效运行
  - **调整**：调整SIEM本质上是减少**误报**（错误地将良性活动、系统状态或配置分类为恶意或易受攻击），同时不产生**漏报**（不对真正的恶意活动或漏洞发出警报）的过程；误报可能会导致分析师疲劳并降低效率

- 7.2.4 出口监控
  - 监控退出和进入网络的流量非常重要，**出口监控**是指监控传出流量以检测组织外部未经授权的数据传输（也称为数据泄露）
    - 用于检测或防止数据泄露的常用方法是数据丢失防护 (DLP) 技术和隐写术监控

- 7.2.5 日志管理
  - **日志管理**：指用于收集、处理、分析和保护日志条目的所有方法（参见上面的SIEM定义）
  - **翻转日志记录**：允许管理员设置最大日志大小，当日志达到该最大值时，系统开始覆盖日志中最旧的事件

- 7.2.6 威胁情报（例如威胁源、威胁搜寻）
  - **威胁情报**：涵盖威胁研究和分析以及新兴威胁趋势的总称；收集有关潜在威胁的数据，包括各种来源的数据，以便及时获取有关当前威胁的信息；经过汇总、转换、分析、解释或丰富的信息，为决策过程提供必要的背景信息
  - **威胁源**：为组织提供稳定的原始数据流，为安全管理员提供威胁源以了解当前的威胁；通过使用这些知识来搜索网络，他们可以进行威胁搜寻，寻找这些威胁的迹象
  - **结构化威胁信息表达 (STIX)**：一种标准化语言，使用基于 JSON 的词典以可读且一致的格式表达和共享威胁情报信息
  - **可信情报信息自动交换 (TAXII)**：威胁情报数据传输的格式； TAXII 是一种传输协议，支持通过安全超文本传输​​协议 (HTTPS) 传输 STIX 见解
  - **威胁狩猎**：主动搜索组织的网络和端点，以识别逃避传统自动化安全工具的恶意活动；威胁狩猎假设攻击者可能已经存在于环境中
  - **杀伤链**：军事模型（攻防兼用）：
    - 通过侦察找到/识别目标
    - 获取目标位置
    - 追踪目标的移动
    - 选择要对目标使用的武器
    - 使用所选武器与目标交战
    - 评估攻击的有效性
  - 组织已针对网络安全采用了此模型：洛克希德马丁公司创建了**网络杀伤链**框架，包括攻击的七个有序阶段：
    - **侦察**：攻击者收集目标信息
    - **武器化**：攻击者识别目标易受攻击的漏洞，以及发送漏洞的方法
    - **传递**：攻击者通过网络钓鱼攻击、恶意电子邮件附件、受感染的网站或其他常见的社会工程方法将武器发送到目标
    - **利用**：该武器利用目标系统上的漏洞
    - **安装**：利用该漏洞的代码然后安装带有后门的恶意软件，允许攻击者远程访问
    - **命令和控制**：攻击者维护一个命令和控制系统，该系统控制目标和其他受感染的系统
    - **针对目标的行动**：攻击者执行其最初的目标，例如盗窃金钱或数据、破坏资产或安装其他恶意代码（例如勒索软件）

- 7.2.7 用户和实体行为分析（UEBA）
  - **UEBA（又名 UBA）**：专注于分析用户和实体行为，作为检测不当或未经授权的活动（例如欺诈、恶意软件、内部攻击等）的一种方式；分析引擎通常包含在 SIEM 解决方案中，或者可以通过订阅添加； UEBA 工具开发个人行为档案并监控用户是否偏离这些档案，这些档案可能表明存在恶意活动和/或帐户受损
  - **基于行为的检测**：又称统计入侵、异常和启发式检测，首先创建正常活动和事件的基线；一旦积累了足够的基线数据来确定正常活动，它就可以检测异常活动（可能表明恶意入侵或事件）
  - 基于行为的 IDS 使用基线、活动统计和启发式评估技术将当前活动与先前活动进行比较，以检测潜在的恶意事件
  - **静态代码扫描技术**：扫描器扫描文件中的代码，类似于白盒测试
  - **动态技术**：扫描器在沙箱中运行可执行文件以观察其行为

## [7.3](#73-perform-configuration-management-cm-eg-provisioning-baselining-automation-osg-10-chpt-16) 执行配置管理 (CM)（例如配置、基线、自动化）(OSG-10 Chpt 16)

- **配置管理（CM）**：是识别、控制和验证组织系统和设置的配置的过程；重点是通过控制 IT 产品和系统的初始化和更改以及在整个生命周期中监视配置来建立和维护 IT 产品和系统的完整性
  - 变更管理的三个基本组成部分：请求控制、变更控制和发布控制
  - CM 是安全配置的一个组成部分，与部署时设备的正确配置相关
  - CM 有助于确保系统以安全、一致的状态部署，并在整个生命周期中保持安全、一致的状态
- **配置**：采用特定的配置基线，制作附加或修改的副本，并将这些副本放入它们所属的环境中；指在新系统上安装和配置操作系统和所需的应用程序
  - 应配置新系统以减少通过默认配置引入的漏洞；关键是根据预期用途强化系统
- **强化系统**：应用安全配置并锁定各种硬件、通信系统、软件（例如操作系统、网络/应用程序服务器、应用程序等）的过程；通常根据互联网安全中心 (CIS) 等行业指南和基准执行；
  - 使其比默认配置更安全，并包括以下内容：
    - 禁用所有未使用的服务
    - 关闭所有未使用的逻辑端口
    - 删除所有未使用的应用程序
    - 更改默认密码
- **基线**：在配置管理的上下文中，基线是系统的起点或起始配置
  - 将基线视为服务列表的一种简单方法；操作系统基线标识了强化特定系统的所有设置
  - 许多组织使用镜像来部署基线；基线映像通过确保始终正确配置所需的安全设置来提高系统的安全性
  - 基线映像通过确保始终正确配置所需的安全设置来提高系统的安全性；它们还减少了部署和维护系统所需的时间，从而降低了总体维护成本
- 自动化：通常创建基线，然后使用自动化方法为特定计算机组添加其他应用程序、功能或设置
  - 请注意，管理员可以使用创建/修改组策略设置来创建域级标准化或进行与安全相关的 Windows 注册表更改

## [7.4](#74-apply-foundational-security-operations-concepts-osg-10-chpt-16) 应用基础安全操作概念 (OSG-10 Chpt 16)

- 安全运营包括涉及保护和维护组织信息系统和资产运营完整性的日常任务、实践和流程；它包括安全监控、事件响应以及安全意识和培训
- 安全运营实践的主要目的是保护信息、系统、设备、设施和应用程序等资产，并帮助组织检测、预防和响应安全威胁
- 实施通用安全操作概念，并定期进行安全审计和审查，体现了应有的谨慎和尽职调查的水平

- 7.4.1 需要知道/最低权限
  - 需要知道：原则将信息或资源的访问权限仅限于需要信息或资源来执行其特定任务或职责的个人
    - 焦点：通过限制某人可以访问的**内容**来保护敏感信息
  - 最小权限：将用户、进程或系统的访问权限限制在执行其工作职能所需的最低级别的原则；规定受试者仅被授予执行指定工作任务所需的特权，而不再获得更多特权
    - 焦点：限制用户或系统拥有的**多少**访问权限（权限）
    - 此上下文中的特权包括数据权限和执行系统任务的权限
    - 基于此概念的限制和控制权限可以保护机密性和数据完整性
    - 原则依赖于这样的假设：所有用户都有工作人员理解的明确定义的工作描述
    - 最小权限通常侧重于确保用户权限受到限制，但它也适用于应用程序或进程（例如，如果应用程序或服务受到损害，攻击者可以假设服务帐户的权限）
  - 需要知道和最小权限原则是安全网络中实施的两个标准 IT 安全原则；它们限制对数据和系统的访问，以便用户和其他主体只能访问他们需要的内容；这种有限的访问有助于防止安全事件，并有助于限制事件发生时的范围；如果不遵守，安全事件会给组织造成更大的损害

- 7.4.2 职责分离 (SoD) 和责任
  - **职责分离 (SoD)**：确保没有一个人能够完全控制关键功能或系统
    - SoD 政策要求两个或更多人串通执行未经授权的活动，从而有助于减少欺诈
    - 如何实施 SoD 的示例是将安全或管理能力和功能分配给多个受信任的个人
  - **两人控制**：（又称两人规则）需要两个人批准关键任务
    - 在组织内使用两人控制可确保同行评审并减少共谋和欺诈的可能性
    - 例如：特权访问管理 (PAM) 解决方案，创建仅供紧急使用的特殊管理员帐户；也许密码被分成两半，因此两个人需要输入密码才能登录
  - **分割知识**：将职责分离和两人控制的概念结合到一个解决方案中；执行操作所需的信息或权限分配给两个或多个用户，确保任何人都没有足够的权限来危害环境的安全； M of N控制是分裂知识的一个例子
    - 最小特权和职责分离等原则有助于防止违反安全策略，而监控有助于阻止和检测尽管使用预防性控制措施但发生的任何违规行为
  - **共谋**：多人协议进行一些未经授权或非法的行为；
    - 实施 SOD、两人控制或分割知识政策有助于通过限制个人在不与他人勾结的情况下可以采取的行动来防止欺诈

- 7.4.3 特权账户管理
  - 特权实体是可信的，但他们可以滥用特权，因此监视特权操作的所有分配至关重要
  - 目标是确保值得信赖的员工不会滥用所授予的特权；监视这些操作还可以检测许多攻击，因为攻击者通常在攻击期间使用特殊权限
  - 高级特权帐户管理实践可以限制用户拥有高级权限的时间
  - **特权帐户管理 (PAM)**：限制对特权帐户的访问或检测帐户何时使用任何提升的权限（例如管理员帐户）的解决方案
    - Microsoft 域，包括本地管理员帐户、域和企业管理员组
    - Linux 包括 root 或 sudo 帐户
  - PAM 解决方案应监控特权帐户、新用户帐户、到路由器表的新路由、更改防火墙配置、访问系统日志和审核文件所采取的操作

- 7.4.4 工作轮换
  - **工作轮换**：（又名职责轮换）是指员工轮换工作或与其他员工轮换工作职责
    - 使用工作轮换作为安全控制可提供同行评审、减少欺诈并实现交叉培训
    - 岗位轮换政策既可以起到威慑作用，也可以起到检测机制的作用

- 7.4.5 服务级别协议 (SLA)
  - **服务级别协议 (SLA)**：组织与外部实体（例如供应商）之间的协议，其中 SLA 规定了性能期望，并且通常包括如果供应商未满足这些期望的处罚
  - **谅解备忘录 (MOU)**：记录两个实体共同努力实现共同目标的意图

## [7.5](#75-apply-resource-protection-osg-10-chpt-16) 应用资源保护 (OSG-10 Chpt 16)

- 媒体管理应考虑所有类型的媒体以及短期和长期需求并评估：
  - 保密性
  - 访问速度
  - 可移植性
  - 耐用性
  - 媒体格式
  - 数据格式
- 对于测试，数据存储介质应包括以下任意一种：
  - 纸
  - 缩微品（缩微胶卷和缩微胶片）
  - 磁性（硬盘、磁盘和磁带）
  - 闪存（SSD 和存储卡）
  - 光学（CD 和 DVD）
- 平均故障间隔时间 (MTBF) 是评估存储介质时的一个重要标准，特别是在涉及有价值或敏感信息的情况下
- 介质管理包括对介质本身的保护，通常涉及政策和程序、访问控制机制、标签和标记、存储、运输、消毒、使用和报废

- 7.5.1 媒体管理
  - **媒体管理**：是指为保护媒体（即任何可以保存数据的东西）以及该媒体上存储的数据而采取的步骤；包括大多数便携式设备（例如智能手机、内存/闪存卡等）
    - 介质在其整个生命周期内受到保护，并在不再需要时被销毁
  - 如上所述，OSG-10 还指磁带介质以及“硬拷贝数据”

- 7.5.2 介质保护技术
  - 如果媒体包含敏感信息，则应将其存储在具有严格访问控制的安全位置，以防止因未经授权的访问而造成损失
    - 用于存储介质的任何位置都应有温度和湿度控制，以防止因损坏而造成损失
  - 媒体管理还可以包括限制计算机系统设备访问的技术控制
  - 当媒体被正确标记、处理和存储时，有助于防止未经授权的披露（机密性丧失）、未经授权的修改（完整性丧失）和未经授权的破坏（可用性丧失）

- 7.5.3 静态数据/传输中数据
  - 这之前已在域 2 中介绍过（请参阅 2.6.4） - 静态数据和传输中的数据可以通过加密进行保护

## [7.6](#76-conduct-incident-management-osg-10-chpt-17) 进行事件管理 (OSG-10 Chpt 17)

- **分析：** 收集和分析有关事件的信息，以确定其范围、影响和根本原因（例如，通过采访目击者、收集和分析证据以及审查系统日志）
- **遏制：**限制事件的影响并防止进一步的损害（例如，通过隔离受影响的系统、更改密码和实施安全控制）
- **根除：** 从环境中消除事件原因（例如，通过删除恶意软件、修补漏洞和禁用受损帐户）
- **事件响应 (IR)**：减少违反安全策略和建议做法的情况；检测和响应事件并减少事件发生时影响的过程； IR 试图在事件发生后尽快保持企业运营或恢复运营
- 事件管理通常由事件响应团队 (IRT) 进行，该团队由具有管理安全事件所需专业知识和经验的人员组成； IRT 负责实施事件响应计划，该计划是一份书面记录，定义了事件响应周期每个阶段要遵循的流程

- 事件响应的主要目标：
  - 提供有效且高效的响应，以减少对组织的影响
  - 维持或恢复业务连续性
  - 防御未来的攻击

- 需要做出一个重要的区分来了解何时应该启动事件响应流程：事件不断发生，并且绝大多数都是无关紧要的；但是，导致某种类型的逆境的事件可以被视为事件，这些事件应触发组织的事件响应流程步骤

  - 事件响应摘要：

    |步骤|舞台|行动/目标|
    |--------|---------------| -----------|
    |准备|||
    | (D) 检测 |分流 |初步评估|
    | (R)回应 |调查|激活IR团队|
    | (M) 诉讼 |降低事件严重性|遏制|
    | (R)报告|文件|与利益相关者沟通|
    | (R)恢复 |恢复 |恢复正常|
    | (R) 补救 |恢复|根本原因；预防|
    | (L) 学到的教训 |恢复|改进流程|

- 考试包括以下步骤（检测、响应、缓解、报告、恢复、补救和经验教训）；您可以使用助记符 DRMRRRL（鼓声）
  - 综上所述：在发现并核实事件后，第一反应是在保护证据的同时限制或遏制事件的范围；根据适用法律，组织可能需要向官方机构报告事件，如果 PII 受到影响，则需要通知个人；补救和吸取教训阶段包括根本原因分析，以确定原因并提出解决方案以防止再次发生
- **准备**：包括制定 IR 流程、分配 IR 团队成员以及与识别事件后发生的情况相关的所有事项；准备工作很重要，并且会预测要遵循的步骤

- 7.6.1 检测
  - **检测：**通过监控和分析安全日志、威胁情报或事件报告来识别潜在的安全事件；如上所述，了解事件和事件之间的区别，检测的目标是识别不良事件（事件）并开始处理它
  - 检测事件的常用方法：
    - 入侵检测和预防系统
    - 反恶意软件
    - 扫描审核日志以查找预定义事件的自动化工具
    - 最终用户有时会发现不规则活动并联系支持人员
  - 注意：收到警报或投诉并不总是意味着事件已经发生

- 7.6.2 响应
  - 检测并验证事件后，下一步是激活事件响应 (IR) 或 CSIRT 团队
  - IR 团队又称为计算机事件响应团队 (CIRT) 或计算机安全事件响应团队 (CSIRT)
  - IR 团队采取的首要步骤之一是进行影响评估，以确定事件的规模、影响可能持续多长时间、还有谁可能需要参与等。
  - IR 团队通常调查事件、评估损害、收集证据、报告事件、执行恢复程序并参与补救和吸取教训阶段，帮助进行根本原因分析
    - 在调查过程中保护所有数据作为证据非常重要，并且不应关闭计算机

- 7.6.3 缓解措施
  - **缓解**：尝试遏制事件；除了进行影响评估外，IR 团队还将尝试尽量减少或控制事件造成的损害或影响
  - IR 团队此时的工作不是解决问题；而是解决问题。只是为了防止进一步的损害
  - 请注意，这可能涉及断开计算机与网络的连接；有时响应者会采取措施缓解事件，但不会让攻击者知道攻击已被检测到

- 7.6.4 报告
  - 报告发生在整个事件响应过程中
  - 一旦事件得到缓解，就会发生正式报告，因为许多利益相关者通常需要了解发生了什么
  - 司法管辖区可能有具体的法律来管理个人身份信息 (PII) 的保护，并且必须报告该信息是否被泄露
  - 此外，一些第三方标准，例如支付卡行业数据安全标准 (PCI DSS)，要求组织向执法部门报告某些安全事件

- 7.6.5 恢复
  - 下一步是恢复，使系统恢复到完全运行的状态
  - **恢复：** 将系统和数据恢复到正常状态（例如，通过从备份恢复、重建系统和重新启用受损帐户）；此时，目标是开始恢复正常
  - 发生事件后恢复系统的最安全方法是从头开始完全重建系统，包括从最近的备份恢复所有数据
    - 有效的配置和变更管理将提供必要的文档，以确保重建的系统配置正确
  - 根据 OSG 的说法，作为恢复的一部分，您应该检查这些区域：
    - 访问控制列表 (ACL)，包括防火墙或路由器规则
    - 服务和协议，确保禁用或删除不需要的服务和协议
    - 补丁
    - 用户帐户，确保它们已从默认配置更改
    - 已知的妥协已被逆转

- 7.6.6 修复
  - **补救**：更改系统配置以立即限制或减少事件再次发生的机会
  - 补救阶段：人员查看事件，确定导致事件发生的原因，然后采取措施防止事件再次发生
  - 补救措施包括执行根本原因分析（检查事件以确定导致其发生的原因），如果根本原因分析发现可以缓解的漏洞，则此阶段将建议进行更改

- 7.6.7 经验教训
  - **经验教训：** 记录事件并从中学习以改进未来的响应（例如，通过确定事件响应过程可以改进的领域并与其他组织分享经验教训）；经验教训阶段是对与事件相关的情况的全面看法，其中包括 IR 团队和其他主要利益相关者在内的人员检查事件和响应，以了解是否有任何经验教训可供吸取
    - 该阶段的输出可以反馈到事件管理的检测阶段
  - IR 团队在完成经验教训审核后通常会创建一份报告
    - 根据调查结果，团队可能会建议更改程序、增加安全控制，甚至更改策略
    - 管理层将决定实施哪些建议，并对他们拒绝的任何建议的剩余风险负责

  - 注意：事件管理不包括对攻击者的反击

## [7.7](#77-operate-and-maintain-detection-and-preventative-measures-osg-10-chpts-111721) 操作和维护检测和预防措施 (OSG-10 Chpts 11,17,21)

- 如[域 1](https://github.com/jefferywmoore/CISSP-Study-Resources/blob/main/CISSP-Domain-1-2024+Objectives.md#1.10) 中所述，部署预防性或预防性控制来阻止或阻止发生不需要的或未经授权的活动
  - 示例：
    - 栅栏
    - 锁
    - 生物识别技术
    - 职责分离政策
    - 岗位轮换政策
    - 数据分类
    - 访问控制方法
    - 加密
    - 智能卡
    - 回调程序
    - 安全政策
    - 安全意识培训
    - 防病毒软件
    - 防火墙
    - 入侵防御系统
- 部署检测控制来发现或检测不需要的或未经授权的活动；侦探控制在事后运作
  - 示例：
    - 保安人员、看门狗
    - 运动探测器
    - 记录和审查安全摄像头捕获的事件
    - 岗位轮换政策
    - 强制休假政策
    - 审计追踪
    - 蜜罐或蜜网
    - 入侵检测系统
    - 违规举报
    - 用户的监督和审查
    - 事件调查
- 一些预防措施：
  - 保持系统和应用程序最新
  - 删除或禁用不需要的服务和协议
  - 使用入侵检测和预防系统
  - 使用最新的反恶意软件
  - 使用防火墙
  - 实施配置和系统管理流程

- 7.7.1 防火墙（例如下一代、Web 应用程序、网络）
  - 防火墙是预防性和技术性控制
  - 防火墙的类型：
    - **静态数据包过滤**：根据预定义的规则（例如IP地址、端口号和协议）检查各个数据包，而不考虑连接状态或数据内容；简单快速，但缺乏上下文感知
    - **应用程序级**：应用程序层（OSI：第 7 层）的功能，充当中介或代理，检查用户和服务之间的流量；可以执行深度数据包检查，这意味着它可以分析数据包的内容以识别恶意内容或针对特定应用程序（例如网络、电子邮件）执行规则；示例：Web 应用程序防火墙 (WAF) 检查流向 Web 服务器的流量，并可以阻止恶意流量，例如 SQL 注入攻击和跨站点脚本 (XSS) 攻击
    - **电路级网关防火墙**：工作在会话层（OSI：第5层），监视TCP握手（即连接建立过程）以确保会话的有效性；一旦会话被验证，它就允许流量通过，而无需进一步检查内容；电路级网关防火墙的处理开销较低，但缺乏深度数据包检查
    - **状态检测防火墙**：在网络和传输层（第 3 层和第 4 层）运行，但维护活动连接的记录（即，它跟踪网络上流量流的状态）；在允许数据包通过之前检查其是否属于活动的合法连接；提供比静态包过滤更好的安全性；缺乏在应用层检查数据的能力
    - **下一代防火墙（NGFW）**：作为统一威胁管理（UTM）设备，将传统防火墙的功能（如状态检测）与深度数据包检测、入侵防御系统（IPS）以及在应用层检测和阻止威胁的能力等附加功能相结合；通常使用沙箱和行为分析等技术结合高级威胁检测； NGFW 在应用程序层和网络层检查流量，提供全面的安全性，包括识别和阻止复杂威胁的能力，但成本更高且资源密集型
    - **内部分段防火墙 (ISFW)**：在网络内用于分段内部流量并控制组织不同部分之间的访问； ISFW 监控和过滤网段之间的流量（例如财务部门和 HR 之间），防止威胁在网络内横向移动；通过监控东西向流量提供内部保护，降低内部威胁或横向移动的风险，可以实施微分段，但配置和管理可能很复杂

    | **防火墙类型** | **OSI 层** | **主要特点** | **优势** | **弱点** |
    |---------------------------|--------------------------|-------------------------------------------------------|-----------------------------------------------------|-----------------------------------------------------|
    | **静态数据包过滤**|第 3 层（网络）|对源/目标 IP 和端口的基本过滤 |快速、低开销|没有上下文感知，无法检查数据负载 |
    | **应用级** |第 7 层（应用程序）|检查应用程序级数据 |深度检查，阻止特定应用|处理开销高，性能慢 |
    | **电路级** |第 5 层（会话）|验证会话建立 |低开销，监控会话有效性 |没有有效负载检查，无法检测更深层次的威胁 |
    | **状态检查** |第 3-4 层（网络、传输）|跟踪会话之间的连接状态 |比静态过滤更好的安全性 |不在应用层检查数据 |
    | **下一代防火墙** |第 3-7 层 |将状态检测与深度数据包检测、IPS 和应用程序控制相结合 |全面的威胁检测、应用感知 |价格昂贵，资源占用率高|
    | **ISFW** |内部细分 |过滤内部网段之间的流量 |防止横向移动，加强微分段 |复杂的配置，通常供内部使用 |

- 7.7.2 入侵检测系统（IDS）和入侵防御系统（IPS）
  - 入侵检测系统 (IDS) 和入侵防御系统 (IPS) 是组织通常用来检测和防止攻击的两种方法
  - **入侵检测**：一种特定形式的监控事件，通常是实时的，以检测表明潜在事件或入侵的异常活动
    - 入侵检测系统 (IDS) 自动检查日志和实时系统事件，以检测入侵尝试和系统故障
    - IDS 是检测多种 DoS 和 DDoS 攻击的有效方法
    - IDS 通过监控网络流量和检查日志来主动监视可疑活动
    - IDS 旨在作为纵深防御安全计划的一部分
    - **基于知识的检测**：又称为基于签名或模式匹配检测，IDS 最常用的方法
    - **基于行为的检测**：又名统计入侵、异常和基于启发式的检测；基于行为的 IDS 使用基线、活动统计数据和启发式评估技术将当前活动与先前活动进行比较，以检测潜在的恶意事件
  - IPS 包括检测功能，您会看到它们被称为入侵检测和预防系统 (IDPS)
    - IPS 包括 IDS 的所有功能，但还可以采取额外的步骤来阻止或防止入​​侵
  - IDS/IPS 应部署在战略网络位置以监控流量（例如在外围或网段之间），并应配置为针对特定类型的扫描和流量模式发出警报
    - 参见 NIST SP 800-94

- 7.7.3 白名单/黑名单
  - 用于控制哪些应用程序运行和哪些应用程序不能运行的方法是通过允许列表和拒绝列表（又称白名单和黑名单）
  - 应用程序白名单或允许列表是一种安全选项，禁止未经授权的软件执行； AKA 默认拒绝或隐式拒绝
  - **允许列表**：标识授权在系统上运行的应用程序列表并阻止所有其他应用程序
  - **拒绝列表**：标识无权在系统上运行的应用程序列表
  - 允许和拒绝列表用于应用程序以帮助防止恶意软件感染
  - 需要注意的重要事项：系统只会使用一个列表，要么允许，要么拒绝
  - 在 iPhone/iPad 上运行的 Apple iOS 是允许列表的极端版本​​的一个示例；用户只能从App Store安装应用程序

- 7.7.4 第三方提供的安全服务
  - 一些组织将审计和渗透测试等安全服务外包给第三方安全服务
  - 一些外部合规实体（例如 PCI DSS）要求组织确保服务提供商合规
  - OSG 还提到一些 SaaS 供应商通过云提供安全服务（例如下一代防火墙、UTM 设备以及用于垃圾邮件和恶意软件过滤的电子邮件网关）

- 7.7.5 沙箱
  - **沙盒**：指一种安全技术，创建一个单独的安全环境来运行和分析未经测试或不受信任的程序或代码，而不会对主机设备或网络造成损害；这种隔离的环境称为**沙箱**，有效地包含代码的执行，使其能够像在正常计算环境中一样运行和表现，但无法影响主机系统或访问关键资源和数据
  - **限制**：限制进程对某些资源的使用，或对某些内存位置的读取和写入；边界是进程在读取或写入时不能超过的内存限制；隔离是使用边界来创建/强制限制
  - 沙盒为应用程序提供了安全边界，并阻止该应用程序与其他应用程序交互；可用作开发、集成或验收测试的一部分，作为恶意软件筛选的一部分，或作为蜜网的一部分

- 7.7.6 蜜罐/蜜网
  - **蜜罐**：作为入侵者或内部威胁的陷阱或诱饵而创建的个人计算机；蜜罐通常具有伪缺陷和虚假数据来引诱攻击者
  - **蜜网**：两个或多个联网的蜜罐一起使用来模拟一个网络；管理员可以观察攻击者在蜜罐中的活动，让他们保持忙碌，而不是攻击生产网络
  - 它们的外观和行为都像合法系统，但它们不托管对攻击者有任何实际价值的数据；管理员经常配置带有漏洞的蜜罐来引诱入侵者对其进行攻击
  - 除了使攻击者远离生产环境之外，蜜罐还允许管理员在不影响实时环境的情况下观察攻击者的活动

- 7.7.7 反恶意软件
  - **广告软件**：显示不需要的广告的软件，有时与间谍软件捆绑在一起
  - **机器人**：攻击者通过命令与控制 (C2) 通道远程控制的受感染计算机；也被称为僵尸
  - **僵尸牧人**：控制僵尸网络的人，使用命令和控制服务器远程控制僵尸对其他系统发起攻击或发送垃圾邮件/网络钓鱼电子邮件；机器人牧民还可以将僵尸网络访问权出租给其他犯罪分子
  - **僵尸网络**：受感染的计算设备（称为机器人或僵尸）的集合，组织在由称为机器人牧民的犯罪分子控制的网络中；  这些许多受感染的系统被整合在一起并一致行动
  - **引导扇区感染程序**：可以将自身安装在驱动器引导扇区中的恶意软件片段
  - **伴侣**：本身没有恶意的帮助软件；它可能类似于实际恶意软件附带的包装程序
  - **无文件恶意软件**：不留下任何痕迹，也不将自身保存到存储设备，但仍然能够在计算机上保持驻留和活动状态
  - **恶作剧/恶作剧**：实际上不是软件，它们通常是社会工程的一部分 - 通过电子邮件或其他方式 - 旨在伤害（恶作剧）或笑话（恶作剧）
  - **逻辑炸弹**：插入程序的恶意软件，当满足稍后的日期/条件时，该程序将激活并执行适合攻击者的功能；将根据某些触发事件执行的代码
  - **宏**：与 Microsoft Office 产品相关，使用简单的编程语言创建以自动执行任务；宏可以被编程为恶意且有害的
  - **恶意软件**：插入系统的程序，其目的是损害受害者的数据、应用程序或操作系统的 CIA；对系统产生负面影响的恶意软件
  - 针对恶意代码最重要的保护是使用具有最新签名文件和启发式功能的反恶意软件
    - 除了过滤互联网内容之外，在每个系统上使用反恶意软件软件的多管齐下有助于保护系统免受感染
    - 遵循最小权限原则，确保用户在系统上没有管理员权限，这样他们就无法安装可能是恶意的应用程序
  - 以下是每种恶意软件类型的特征：
    - **病毒**：在所有者不直接知情/合作的情况下，出于复制和传播自身意图/能力而编写的软件； *定义特征是它是一款必须由用户以某种方式触发的恶意软件*；修改其他程序以包含其自身可能已更改版本的程序
      - 病毒使用四种主要传播技术：
        - 文件感染
        - 服务注入
        - 引导扇区感染
        - 宏观感染
    - **多方**：表示恶意软件以不同方式传播（例如 Stuxnet）
    - **多态**：恶意软件在复制时可以改变自身的各个方面以逃避检测（例如文件名、文件大小、代码结构等）
    - **勒索攻击**：威胁破坏、否认或未经授权公开发布/再营销私人信息资产的任何形式的攻击；通常涉及加密资产并扣留解密密钥直至支付赎金
    - **勒索软件**：一种恶意软件，通常会对系统或系统网络进行加密，有效地将用户锁定在门外，然后要求支付赎金（通常以数字货币的形式）以获得解密密钥
    - **rootkit**：与隐形恶意软件类似，rootkit 试图掩盖其在系统上的存在；深深嵌入操作系统的恶意软件；该术语源自 root 和黑客工具实用工具包的概念； root 是指获得对系统的全部或全部控制权；通常包括攻击者可以根据特定目标利用的恶意软件工具的集合
    - **间谍软件**：秘密监视和收集用户信息的软件
    - **隐形**：使用各种主动技术来逃避检测的恶意软件
    - **特洛伊木马**：特洛伊木马是一种看似无害或可取但包含恶意代码的恶意软件；木马通常存在于易于下载的软件中；特洛伊木马将后门或陷门插入其他程序或系统
    - **蠕虫**：软件编写的目的/能力是在所有者不知情/不合作的情况下进行复制和传播，但不需要修改其他程序以包含其自身的副本；通过利用网络或一系列系统中的漏洞，可以自行传播和传播的恶意软件
    - **零日**：是以前从未在野外见过的任何类型的恶意软件，受影响产品的供应商不知道（或尚未发布补丁），创建旨在保护系统的反恶意软件软件的安全公司也是如此；以前未报告的漏洞，在系统所有者/开发人员检测并纠正漏洞之前，这些漏洞可能会被利用而不会被检测或预防；得名于“零时间”，即系统所有者或构建者首次识别出漏洞利用或漏洞的时间；又称零时漏洞、零日攻击；缓解措施包括基本的安全实践，包括禁用不需要的协议/服务、使用适当的防火墙、IDS/IPS 和蜜罐

- 7.7.8 基于机器学习和人工智能（AI）的工具
  - **人工智能**：赋予机器做人类可以做得更好的事情的能力，或者允许机器执行我们以前认为需要人类智能的任务
  - **机器学习**：人工智能的一个子集，指的是可以通过经验自动改进的系统
    - 机器学习系统始于一组规则或指南；机器学习技术尝试通过算法从数据集中发现知识
    - ML和AI都需要训练数据，但人类定义的结构水平不同
  - 基于行为的检测是机器学习和人工智能应用于网络安全的一种方式
    - 管理员关联网络上正常活动和流量的基线；这种情况下的基线类似于给机器学习系统的一组规则
    - 在正常操作期间，它检测异常并报告它们；如果检测结果为误报（将良性活动、系统状态或配置错误地分类为恶意或易受攻击），机器学习系统会学习
  - 人工智能系统在没有基线的情况下启动，监控流量并根据其观察到的流量慢慢创建自己的基线
    - 当它创建基线时，它也会寻找异常情况
    - 人工智能系统还依赖于管理员的反馈来了解警报是否有效或误报
  - **神经网络**：尝试通过安排一系列分层计算来模拟人脑的功能来解决问题；神经网络需要对特定问题进行大量训练才能提供解决方案
  - **专家系统**：人工智能的一个分支，利用基于知识的系统来模拟人类专家的决策能力；专家系统有两个主要组件：使用一系列 if/then 规则的知识库，以及利用该信息得出有关其他数据的结论的推理引擎

## [7.8](#78-implement-and-support-patch-and-vulnerability-management-osg-10-chpt-16) 实施和支持补丁和漏洞管理 (OSG-10 Chpt 16)

- **漏洞管理**：识别、评估、确定优先级和修复信息系统缺陷所需的活动
- 漏洞管理包括常规漏洞扫描和定期漏洞评估
  - vuln 扫描器可以检测已知的安全漏洞和弱点，例如缺少补丁或弱密码
  - 漏洞扫描器生成的报告表明系统的技术漏洞，并且是对补丁管理程序的有效检查
  - 漏洞评估不仅仅限于技术扫描，还可以包括审查和审计以检测漏洞
- 补丁和漏洞管理流程协同工作，帮助保护组织免受新出现的威胁；补丁管理确保应用适当的补丁，漏洞管理有助于验证系统不易受到已知威胁的影响
- **补丁**：（又名更新、快速或热修复）为纠正错误或漏洞或提高现有软件性能而编写的任何类型代码的总称；安装后，补丁会直接修改文件或设备设置，而不更改相关软件组件的版本号或发布详细信息
  - 在安全方面，管理员主要关注安全补丁，这些补丁会影响系统的漏洞
- **补丁管理**：操作系统和应用程序代码修订（称为补丁、修补程序和服务包）的系统通知、识别、部署、安装和验证
  - 有效的补丁管理程序通过评估、测试、批准和部署适当的补丁来确保系统与当前补丁保持同步
- **补丁星期二**：几个大型科技组织（例如 Microsoft、Adobe、Oracle 等）定期在每月的第二个星期二发布补丁
- 补丁管理通常与变更和配置管理交织在一起，确保文档反映变更；当组织没有有效的补丁管理计划时，它可能会遇到本可以避免的已知问题造成的中断和事件
- 确定补丁级别的方法有以下三种：
  - 代理：设备上安装的更新软件（代理）
  - 无代理：远程连接到每个设备
  - 被动：监控流量以推断补丁级别
  - 可以手动或自动部署补丁
- 有效计划中的常见步骤：
  - 评估补丁：确定它们是否适用于您的系统
  - 测试补丁：在隔离的非生产系统上测试补丁，以确定补丁是否会导致任何不需要的副作用
  - 批准补丁：测试成功后，补丁被批准部署；使用变更管理作为审批流程的一部分是很常见的
  - 部署补丁：测试通过后，部署补丁；许多组织使用自动化方法通过第三方或软件供应商部署补丁
  - 验证补丁是否已部署：定期测试和审核系统以确保它们保持补丁状态
  - 定期识别漏洞、对其进行评估，并采取措施减轻与之相关的风险
  - 不可能消除风险，也不可能消除所有漏洞
  - 漏洞管理计划有助于确保组织定期评估漏洞并减轻那些代表最大风险的漏洞
  - 组织内最常见的漏洞之一是未打补丁的系统，因此漏洞管理程序通常会与补丁管理程序结合使用

## [7.9](#79-understand-and-participate-in-change-management-processes-osg-10-chpt-16) 了解并参与变更管理流程 (OSG-10 Chpt 16)

- **变更管理**：组织用于从当前状态过渡到未来状态的正式流程；通常包括请求、评估、批准、实施、验证和了解变更的机制；确保分析变更的成本和收益，并以受控方式进行变更以降低风险
  - 变更管理流程允许各种 IT 专家在实施之前审查提议的变更是否会产生意外后果
  - 变更管理控制提供了控制、记录、跟踪和审核所有系统变更的流程
- 变更管理流程包括多个相互依赖的步骤：
  - 变更请求：变更请求可以来自组织的任何部分，并且几乎涉及任何主题；公司通常使用某种类型的变革管理软件
  - 评估影响：提出变更请求后，无论请求多么小，都必须评估潜在变更的影响
  - 批准/拒绝：根据请求的变更和相关影响评估，常识在批准过程中发挥着重要作用
  - 构建和测试：批准后，任何更改都应该开发和测试，最好是在测试环境中
  - 时间表/通知：在实施任何变更之前，应通知主要利益相关者
  - 实施：经过测试并通知利益相关者后，应实施变更；制定回滚计划非常重要，允许人员撤消更改
  - 验证：一旦实施，应再次通知高级管理层和利益相关者验证变更
  - 记录变更：每一步都应进行记录；确保所有文档完整并确定与给定变更相关的版本和基线至关重要
- 当实施变更管理流程时，它会为系统的所有变更创建文档，如果人员需要撤销变更或在其他系统上进行相同的变更，则提供信息线索
- 变更管理控制是 ISO 通用标准中某些安全保证要求 (SAR) 的强制性要素

## [7.10](#710-implement-recovery-strategies-osg-10-chpt-18) 实施恢复策略 (OSG-10 Chpt 18)

- **恢复策略**：中断后恢复关键业务组件、系统和运营的计划
- **灾难恢复 (DR)**：使组织能够在灾难性事件发生后最大限度地减少关键任务技术基础设施的损失并恢复其的一组实践
- **业务连续性 (BC)**：使组织能够在发生任何破坏性事件期间和之后继续履行其关键职能的一组实践

- 7.10.1 备份存储策略（例如云存储、现场、异地）
  - 备份策略由组织目标驱动，通常关注备份和恢复时间以及存储需求；目标是确定数据的存储方式和位置，以便在发生数据丢失、损坏或灾难时进行恢复
  - 3-2-1规则：
    - 3份关键文件副本
    - 不同介质上的 2 个备份
    - 1 个异地备份
  - 现场备份：将备份数据存储在与源数据相同的位置（也称为本地备份）；现场备份的缺点是，如果由于某种灾难您丢失了源数据，您也有可能丢失备份
  - 异地备份：将备份数据存储在与原始数据存储不同的位置；异地位置应该在地理位置上远离源数据，或者距离源数据足够远，以便单一灾难不会损害两者
  - 云备份：将备份数据存储在云端，具有存储扩展性、高可用性、按需付费等优点

  - **存档位**：指示相对于给定备份策略的备份状态的技术细节（元数据）
    - 0 = 文件已备份（没有新的更改）
    - 1 = 自上次备份以来文件已被修改（需要备份）
  - 不同的备份策略对归档位的处理方式不同；增量备份和差异备份策略不会以相同的方式处理存档位
    - 完整备份完成后，每个文件的存档位都会重置、关闭或设置为 0
  - 三种备份类型：
    - **完整备份**：存储受保护设备或备份介质上包含的数据的完整副本；无论存档位的设置如何，完整备份都会复制系统上的每个文件
    - **增量备份**：仅备份自上次备份以来发生更改的数据（无论是完整备份还是增量备份）
      - 仅复制存档位打开、启用或设置为 1 的文件
      - 增量备份完成后，所有重复文件上的存档位都会重置、关闭或设置为 0
    - **差异备份**：自上次完整备份以来的更改
      - 仅复制存档位打开、启用或设置为 1 的文件
      - 与完整备份和增量备份不同，差异备份过程不会更改存档位
    - 增量备份和差异备份之间最重要的区别是在紧急情况下恢复数据所需的时间
      - 完整备份和差异备份的组合只需要恢复两个备份：最近的完整备份和最近的差异备份
      - 完整备份与增量备份的组合将需要恢复最近的完整备份以及自该完整备份以来执行的所有增量备份
      - 差异备份的恢复时间较短，但创建时间比增量备份要长
    - 注意：祖父/父亲/儿子、河内塔和六盒每周都是轮换备份介质、平衡介质重用与数据保留问题的不同方法
      - 祖父/父亲/儿子（GFS）：三个或更多备份周期，例如每日、每周、每月；每日备份使用 FIFO 系统每 3 个月轮换一次，每周备份同样每两年轮换一次，每月备份每年一次
      - 河内塔：基于同名谜题，其中第一个备份每隔一天覆盖一次，第二个备份每四天覆盖一次，第三个备份每隔一天覆盖一次，增量与第一个备份不同
      - 每周六个磁带：一种方法，涉及一周中的每一天使用六种不同的介质（磁带、磁带、驱动器等）；许多不需要备份大量数据的小型企业都使用这种类型的磁带轮换计划，通常包括在周一和周四之间使用四种介质进行增量和差异备份

    - 备份存储最佳实践包括将介质副本保留在至少一个异地位置，以便在主位置不可用、无法工作或被破坏时提供冗余；常见的策略是将备份存储在云服务中，该云服务本身在地理上是冗余的
    - 两种常见的备份策略：
        1）周一晚上进行完整备份，然后每周每隔一个晚上运行差异备份
            - 如果周六早上发生故障，则恢复周一的完整备份，然后仅恢复周五的差异备份
        2）周一晚上进行完整备份，然后每周每隔一个晚上运行增量备份
            - 如果周六早上发生故障，则恢复周一的完整备份，然后按原始时间顺序恢复每个增量备份

        |特色|完整备份|增量备份|差异备份|
        |---------------|------------------|-----------------------|--------------|
        | **描述** |所有选定数据的完整副本 |仅备份自上次备份以来发生更改的数据（无论类型如何）|备份自上次完整备份以来所做的所有更改 |
        | **存储空间** |需要最多的存储空间 |需要最少的存储空间 |需要比增量更多的空间，但小于完整的空间 |
        | **备份速度** |最慢，因为它复制所有数据 |最快，因为它只复制自上次备份以来更改的数据 |比完整备份快但比增量慢，因为它复制自上次完整备份以来的所有更改 |
        | **恢复速度** |最快，因为所有数据都集中在一个地方 |最慢，因为可能需要多个增量备份才能恢复到特定点 |比增量备份更快，因为它需要最后一次完整备份和最后一次差异备份 |
        | **复杂性** |最简单，不依赖于以前的备份 |复杂，因为它依赖于从上次完整备份到最近增量备份的一系列备份 |比增量简单，需要最后一次完整备份和最后一次差异备份才能恢复 |
        | **最佳用例** |当备份时间和存储空间不是问题时 非常适合不太频繁的备份 |适合日常变化极少且需要快速备份的环境 |非常适合存储空间有限但恢复时间需要相对较快的环境 |

    - 用于创建数据库内容异地副本的三种主要技术：电子保管库、远程日志记录和远程镜像
      - **电子保管库**：使用批量传输将数据库备份移动到远程站点
      - **远程日志**：数据传输以更快捷的方式进行；远程日记与电子保管库类似，传输到远程站点的事务日志不会应用于实时数据库服务器，而是保存在备份设备中
      - **远程镜像**：最先进的数据库备份解决方案，也是最昂贵的，通过远程镜像，在备份站点维护一个实时数据库服务器；远程服务器接收数据库修改的副本，同时将它们应用于主站点的生产服务器

- 7.10.2 恢复站点策略（例如，冷与热、资源容量协议）
  - 非灾难：服务中断，影响重大但有限
  - **灾难**：导致整个站点一天或更长时间无法使用的事件（通常需要备用处理设施）
  - **自然灾害**：通常威胁组织的事件，包括地震、洪水、风暴、火灾、海啸和火山爆发
  - **人为灾难**：爆炸、电气火灾、恐怖行为、停电和其他公用设施故障、硬件/软件故障、劳动力困难、盗窃、破坏等。
  - 灾难：重大破坏导致设施完全毁坏
    - 对于灾难和灾难，组织有 3 个基本选项：
      - 使用组织拥有/运营的专用站点
      - 租赁商业设施（热地、暖地、冷地）
      - 与另一个机构/组织签订正式协议
    - 当灾难中断业务时，灾难恢复计划应该几乎自动启动并开始为恢复操作提供支持
      - 除了提高您的应对能力之外，购买保险还可以减少财务损失的影响
    - 恢复站点策略考虑组织的多个要素，例如人员、数据、基础设施和成本，以及可用性和位置等因素
    - 在设计灾难恢复计划时，重要的是要牢记您的目标 - 将工作组恢复到可以在平常工作地点恢复活动的程度
      - 有时最好为不同的工作组开发单独的恢复设施
    - 为了以尽可能高的效率恢复业务运营，您应该设计灾难恢复计划，以便首先恢复那些优先级最高的业务部门
  - **互助协议 (MAA)**：提供灾难恢复站点的廉价替代方案； *不常用*因为它们很难执行；参与 MAA 的组织也可能因同一灾难而关闭，MAA 引发保密问题
  - **资源容量协议**：预先安排的供应商协议，以确保发生中断事件后所需的必要资源；目标是确保组织能够访问恢复站点的资源

- 7.10.3 多个处理地点
  - 构建完全有弹性的恢复流程意味着包括灾难恢复场景的替代处理站点；多个处理地点增加了地理多样性以及对灾难事件的抵御能力
  - 灾难恢复计划最重要的要素之一是选择主站点不可用时使用的备用处理站点
    - **冷站点**：备用设施足够大，足以处理组织的处理负载，并配备适当的电力和环境支持系统
      - 冷站点没有预装任何计算设施（硬件或软件）
      - 冷站点没有有效的宽带通信链接
      - 优点：
        - 冷站点是最便宜的选择，也许也是最实用的选择
      - 缺点：
        - 激活网站的巨大延迟通常以几周为单位，这可能会产生错误的安全感
        - 难以测试
    - **暖场地**：暖场地比冷场地好，因为除了建筑物的外壳外，还安装了基本设备
      - 热站点包含开始恢复操作所需的数据链路和预配置设备，但没有可用的信息数据
      - 然而，与热站点不同的是，热站点通常不包含客户端数据的副本
      - 从宣布灾难之日起，热站点的激活通常需要至少 12 小时
    - **热点站点**：配备硬件和软件的全面运行的异地数据处理设施；保持持续工作状态的备份设施，配有全套服务器、工作站和通信链路
      - 热门网站通常是订阅服务
      - 主站点服务器上的数据定期或持续复制到热点站点的相应服务器上，确保热点站点拥有最新的数据
      - 优点：
        - 无与伦比的灾难恢复保护水平
      - 缺点：
        - 成本极高，可能会使组织的硬件、软件和服务预算增加一倍，并且需要使用额外的员工来维护站点
        - 拥有（根据定义）所有生产数据的副本，因此增加了攻击面
    - **移动站点**：传统恢复站点的非主流替代品；通常配置为冷站点或热站点，如果您的灾难恢复计划取决于工作组恢复策略，则移动站点是实施该方法的绝佳方法
      - 云计算：许多组织现在转向云计算作为首选的灾难恢复选项
        - 一些维护自己数据中心的公司可能会选择使用这些 IaaS 选项作为备份服务提供商
      - 注意：热门站点是订阅服务，而冗余站点则相反，是由组织拥有和维护的站点（并且冗余站点在功能方面可能是“热门”）
        - 考试区分热点站点（订阅服务）和冗余站点（由组织拥有）
    - 云计算：组织越来越多地转向云计算（通常通过 IaaS）作为首选灾难恢复选项

- 7.10.4 系统弹性、高可用性（HA）、服务质量（QoS）和容错
  - **系统弹性**：系统在发生不良事件期间维持可接受的服务水平的能力
    - **高可用性 (HA)**：使用冗余技术组件使系统在经历短暂中断后能够快速从故障中恢复
      - **集群**：指一组系统一起工作来处理工作负载；经常出现在使用负载均衡器来管理传入流量并将请求分发到多个 Web 服务器（集群）的 Web 服务器的上下文中
      - **冗余**：与所有成员一起工作的集群不同，冗余通常涉及主系统和辅助系统；主系统完成所有工作，辅助系统处于备用模式，除非主系统发生故障，此时活动可以故障转移到辅助系统
        - 集群和冗余都将高可用性作为其配置的副产品
    - **服务质量 (QoS)**：控制措施可保护负载下数据网络的可用性
      - 许多因素都会影响最终用户体验的质量，而 QoS 会尝试管理所有这些因素以创建满足业务需求的体验
      - 影响 QoS 的因素：
        - 带宽：可用于承载通信的网络容量
        - 延迟：数据包从源到目的地所需的时间
        - 丢包：部分数据包在源和目的之间可能丢失，需要重传
        - 干扰：电噪声、故障设备和其他因素可能会损坏数据包的内容
    - **容错**：系统遭受故障但继续运行的能力
    - **独立磁盘冗余阵列（RAID）**：是指在系统中同时使用多个驱动器以实现更高的速度或可用性；最知名的 RAID 级别是：
      - RAID 0 — 条带化：提供显着的速度、写入和读取优势
      - RAID 1 — 镜像：使用冗余来提供可靠的数据可用性
      - RAID 5—奇偶校验保护：至少需要三个驱动器，并在 RAID 0 和 RAID 1 之间提供经济高效的平衡； RAID 5 利用通过 XOR 运算计算出的奇偶校验位来存储和恢复数据
      - RAID 6—双奇偶校验：与 RAID 5 类似，但使用两个奇偶校验块，允许两个驱动器同时发生故障而不会丢失数据；至少需要四个驱动器
      - RAID 10 — 镜像和条带化：至少需要四个驱动器，并在一个解决方案中提供条带化（速度）和镜像（可用性）的优势；这种类型的 RAID 通常是最昂贵的之一

    |备份方法|成本影响| RPO 的时间影响 |
    |---------------|----------------------------------------------------------------------------|-----------------------------------------------|
    |增量 |由于仅备份更改，因此存储要求降低，从而降低了成本 |恢复时间较长，因为它需要最后一次完整备份以及所有后续增量备份，直到 RPO |
    |差速器|成本适中；需要比增量更多的存储，但比完整的存储少，因为它存储自上次完整备份以来的所有更改|比增量恢复更快，因为它需要最后一次完整备份和最后一次差异备份直至 RPO |
    |复制|由于需要随时准备接管的复制环境，因此成本较高；连续的数据复制也会增加带宽成本|由于数据不断更新，恢复时间最短，可近乎即时恢复到故障前的最新点 |
    |聚类|成本最高，因为它涉及多个服务器（集群）协同工作以提供高可用性和冗余 |恢复时间最短，因为系统专为立即故障转移而设计，不会丢失数据，确保可以立即满足 RPO |

    |站点恢复方法|成本影响| RTO 的时间影响 |
    |----------------------|-----------------------------------------------------------------------------------|---------------------------------------------------|
    |冷场|成本最低的选择；设施和基础设施已具备，但设备和数据需要在灾后建立|最长的恢复时间，因为必须配置系统和数据并从备份中恢复 适用于具有更灵活 RTO 的非关键应用 |
    |温馨站点 |成本适中；冷站点和热站点之间的折衷，包括一些可以快速激活的预装硬件和连接 |由于基础设施已部分准备就绪，但数据和系统可能仍需要更新才能完全运行，恢复速度比冷站点更快 |
    |热门网站 |成本高；原始站点的副本，具有完整的计算机系统和近乎实时的数据复制，并准备好立即接管运营|最短的恢复时间，专为无缝接管最新数据和系统而设计，允许关键操作在几乎没有停机时间的情况下继续进行 |
    |冗余站点|成本最高；本质上作为主动-主动配置运行，其中两个站点同时运行，相互完全镜像 |即时恢复，因为冗余站点已经与主站点并行运行，确保服务不中断 |

## [7.11](#711-implement-disaster-recovery-dr-processes-osg-10-chpt-18) 实施灾难恢复 (DR) 流程 (OSG-10 Chpt 18)

- **业务连续性管理 (BCM)**：组织负责创建、维护和测试 BCP 和 DRP 计划的流程和功能
- **业务连续性规划 (BCP)**：重点关注业务流程在受到意外影响时的生存
- **灾难恢复计划 (DRP)**：重点关注重要技术基础设施和系统的恢复
  - BCM、BCP 和 DRP 最终用于实现相同的目标：业务及其关键和必要功能、流程和服务的连续性
- BCP/DRP 的关键步骤是：
  - 制定应急计划政策
  - 进行BIA
  - 识别控制
  - 制定应急策略
  - 制定应急计划
  - 确保测试、培训和演习
  - 维护

- 作为业务影响分析 (BIA) 的一部分，BCP 和 DRP 程序的四个关键衡量标准：
  - **RPO（恢复点目标）**：及时测量的最大可容忍数据丢失
  - **RTO（恢复时间目标）**：将系统恢复到定义的服务水平的最大容忍时间；指定业务连续性规划人员认为灾难后恢复服务可接受的时间量
  - **WRT（工作恢复时间）**：作为恢复正常操作的一部分，可用于验证系统和数据完整性的最大时间
  - **MTD（最大可容忍停机时间）**：在对业务造成不可接受/不可恢复的后果之前可以中断的最大时间关键型系统、功能或流程

- 7.11.1 响应
  - 灾难恢复计划应包含简单而全面的指示，供重要人员在认识到灾难正在发生或即将发生时立即遵循
  - 紧急响应计划通常以清单的形式提供给响应者；按优先级顺序排列清单任务，最重要的任务排在第一位！
  - 响应计划应包括启动灾难恢复计划的明确标准，定义谁有权宣布灾难，然后讨论通知程序

- 7.11.2 人员
  - 灾难恢复计划应包含发生灾难时要联系的人员名单
    - 通常包括 DRP 团队的主要成员以及关键人员
  - 企业需要确保员工接受有关灾难恢复程序的培训，并确保他们拥有实施灾难恢复计划所需的资源
  - 为灾难恢复准备人员和程序所涉及的关键活动包括：
    - 制定灾难恢复培训计划
    - 定期进行灾难恢复演习
    - 为员工提供实施灾难恢复计划所需的资源和工具
    - 向所有员工传达灾难恢复计划

- 7.11.3 通信（例如方法）
  - 确保响应清单为急救人员提供明确的计划，以保护生命和财产并确保操作的连续性
    - 应向所有可能应对灾难的人员提供通知清单
    - 提供的信息应包括备用联系方式（例如手机或备用、寻呼机等）以及每个角色的备用联系人

- 7.11.4 评估
  - 当灾难恢复团队到达时，他们的首要任务之一就是评估情况；初始响应人员进行快速评估，对事件进行分类并开始响应，然后进行更详细的评估，以衡量有效性并根据情况的发展确定资源的优先顺序

- 7.11.5 恢复
  - 注意恢复和恢复是不同的概念
  - **恢复**：使商业设施和环境恢复到可用状态
  - **恢复**：使业务运营和流程恢复到工作状态
  - 系统恢复包括恢复发生故障或崩溃时系统上正在使用的所有受影响的文件和服务
  - 在设计灾难恢复计划时，重要的是要牢记您的目标 - 将工作组恢复到可以在平常工作地点恢复活动的程度

- 7.11.6 培训和意识
  - 与业务连续性计划一样，您必须为参与灾难恢复工作的所有人员提供培训
  - 设计培训计划时请考虑以下因素：
    - 为所有新员工进行入职培训
    - 为首次担任新灾难恢复角色的员工提供初步培训
    - 为灾难恢复团队成员提供详细的复习培训
    - 为所有其他员工提供简短的意识复习

- 7.11.7 经验教训
  - 在任何灾难恢复操作或其他安全事件结束时都应举行经验教训会议
  - 经验教训流程旨在为参与事件响应工作的每个人提供反思个人角色和团队整体响应的机会
  - 在记忆消失之前，时间对于吸取教训至关重要
  - 通常，经验教训会议由经过培训的协调员主持
  - NIST SP 800-61 提供了一系列在经验教训过程中使用的问题：
    - 究竟发生了什么以及在什么时间发生的？
    - 工作人员和管理层在处理该事件方面表现如何？
    - 是否遵循了书面程序？
    - 程序是否充分？
    - 是否采取了任何可能阻碍复苏的步骤或行动？
    - 下次发生类似事件时，工作人员和管理层会采取哪些不同的做法？
    - 如何改进与其他组织的信息共享？
    - 哪些纠正措施可以防止今后发生类似事件？
    - 今后应注意哪些先兆或指标以发现类似事件？
    - 需要哪些额外的工具或资源来检测、分析和缓解未来的事件？
    - 团队负责人在报告中记录吸取的教训，其中包括建议的流程改进措施

## [7.12](#712-test-disaster-recovery-plans-drp-osg-10-chpt-18) 测试灾难恢复计划 (DRP) (OSG-10 Chpt 18)

- 每个灾难恢复计划都必须定期进行测试，以确保计划的规定可行并满足组织不断变化的需求
- 五种主要测试类型：
  - 通读/清单测试
  - 结构化演练
  - 模拟测试
  - 并行测试
  - 全中断测试

- 7.12.1 通读/桌面
  - **通读测试**：最简单的测试之一，但也是最关键的测试之一；灾难恢复计划的副本将分发给灾难恢复团队的成员进行审查，以实现三个目标：
    1）确保关键人员了解自己的职责并定期更新这些知识
    2）为个人提供审查和更新计划、删除过时信息的机会
    3) 帮助识别关键人员离开公司以及需要重新分配 DR 职责的情况（请注意，DR 职责应包含在职位描述中）

  - **桌面**：灾难恢复团队成员和主要利益相关者聚集在一起讨论如何应对灾难场景的练习，而不会实际中断系统或操作

- 7.12.2 演练
  - **演练**：范围可能有所不同，但一般来说，演练是更实际的灾难恢复练习；这是一种程序测试，参与者遵循灾难恢复计划来验证流程和任务是否准确、完整和可行

- 7.12.3 模拟
  - **模拟测试**：类似于演练，向团队成员展示一个场景并要求他们制定适当的响应
    - 与通读和演练不同，其中一些响应措施随后会进行测试
    - 这可能涉及非关键业务活动的中断以及使用一些操作人员

- 7.12.4 并行
  - **并行测试**：代表下一个级别，涉及将人员重新安置到备用恢复站点并实施站点激活程序
    - 重新安置的员工像处理实际灾难一样履行灾难恢复职责
    - 主要设施的运营不会中断

- 7.12.5 完全中断
  - **完全中断测试**：像并行测试一样操作，但涉及实际关闭主站点的操作并将其转移到恢复站点
    - 这些测试涉及重大风险（关闭主站点、传输恢复操作，然后进行相反的操作），因此极难安排（管理层可能会抵制这些测试）
    - 全中断测试证明容灾方案确实有效

- 7.12.6 沟通（例如利益相关者、测试状态、监管机构）
  - 在开始 DRP 测试之前，重要的是要告知所有利益相关者预期的结果，包括计划的时间、潜在的影响、测试的目标
  - 在测试过程中，定期提供更新非常重要，特别是对于更大规模的全中断测试，确保利益相关者了解进度、挑战和最终变化
  - 测试后的汇报会可用于审查结果、查看成功之处和需要改进的领域
  - 许多具有严格法规的行业都需要特定的灾难恢复测试计划，让监管机构了解情况对于合规性和治理非常重要

## [7.13](#713-participate-in-business-continuity-bc-planning-and-exercises-osg-10-chpt-3) 参与业务连续性 (BC) 规划和演习 (OSG-10 Chpt 3)

- 业务连续性规划解决了发生重大中断后如何保持组织正常运转
  - 需要注意的是，其范围比 DR 的范围要广泛得多
  - 安全领导者可能会参与，但不一定领导 BCP 工作
- BCP 的四个主要步骤是：
  - 项目范围及规划
  - 业务影响分析 (BIA)
  - 连续性规划
  - 规划批准及实施
  

## [7.14](#714-implement-and-manage-physical-security-osg-10-chpt-10) 实施和管理物理安全 (OSG-10 Chpt 10)

- 部署物理访问控制机制来控制、监控和管理对设施的访问
  - 场地内的部分、分区或区域应明确指定为公共、私人或带有适当标牌的限制区域

- 7.14.1 周边安全控制
  - 围栏是一种边界限定装置，可以由以下部分组成：
    - 地上画的条纹
    - 链环围栏
    - 铁丝网
    - 混凝土墙
    - 使用激光、运动或热检测来实现隐形周界
    - **周界入侵检测和评估系统（PIDAS）**：一种先进的围栏形式，有两个或三个围栏协同使用以优化安全性；栅栏之间的空间可以作为警卫巡逻或徘徊的看门狗的走廊；一个或多个栅栏可以支持触摸检测功能；外部围栏用于防止动物和偶然侵入者进入主围栏，从而降低误报率 (NAR) 或误报
    - **门**：栅栏或墙壁上的受控出口和入口点
    - **旋转栅门**：一种门的形式，可同时防止多人进入，并且通常限制一个方向的移动
    - **访问控制前厅**：（又称陷阱）一套双门，通常由警卫或其他物理布局保护，防止搭载，并且可以根据安全人员的判断将人员困住
    - **安全护柱**：物理安全的关键要素，可防止车辆撞击接入点和入口
    - **路障**：除了围栏之外，还用于控制人流和车辆
    - 照明是最常用的周界安全控制形式，提供威慑的安全优势（主要目的是阻止偶然入侵者、侵入者等）
    - 保安人员能够适应条件和情况并做出反应；看门狗可以作为周边控制的替代方案，起到检测和威慑作用
    - 所有物理安全控制最终都依赖于人员干预和阻止实际的入侵和攻击
    - 物理安全的 KPI（关键绩效指标）是关键安全方面的运行或故障的度量或测量；应对它们进行监控、记录和评估

- 7.14.2 内部安全控制
  - 在任何情况和条件下，安全最重要的方面是保护人员
  - 内部安全控制包括锁、徽章、保护分配系统 (PDS)、运动探测器、入侵警报和辅助验证系统
  - 如果设施设计有限制区域来控制物理安全，则需要一种处理访客的机制
    - **访客日志**：非员工条目或对设施/位置的访问的手动（或自动）列表
      - 物理访问日志可以为逻辑日志的解释建立上下文
  - 锁：旨在防止未经适当授权的访问；锁是一种原始形式的识别和授权机制

## [7.15](#715-address-personnel-safety-and-security-concerns-osg-10-chpt-16) 解决人员安全和安保问题 (OSG-10 Chpt 16)

- 7.15.1 旅行
  - 对人员进行旅行时安全实践培训可以提高他们的安全性并预防安全事故：
    - 敏感数据：与员工一起旅行的设备不应包含敏感数据
    - 恶意软件和监控设备：可能性包括安装在外国酒店房间的物理设备
    - 免费 wi-fi：听起来很吸引人，但可以用来捕获用户的流量
    - VPN：雇主应该有权访问可用于创建安全连接的 VPN

- 7.15.2 安全培训和意识（例如，内部威胁、社交媒体影响、双因素身份验证 (2FA) 疲劳）
  - 组织应将人员安全和安保主题添加到其培训和意识计划中，并帮助确保人员了解胁迫系统、旅行最佳实践、应急管理计划以及一般安全和安保最佳实践
  - 培训计划应强调保护人员的重要性
  - 内部威胁：应教育员工了解员工、承包商或业务合作伙伴访问或滥用公司数据的风险，强调潜在内部威胁的迹象以及报告可疑行为的方法
  - 社交媒体影响：教育员工了解社交平台上过度分享的风险，例如社交媒体。使用公开信息进行社会工程攻击的可能性
  - 2FA/MFA 疲劳：向员工宣传 MFA 疲劳攻击，攻击者会发送重复的推送通知，希望用户批准；应培训员工绝不批准他们未发起的 MFA 提示，并立即报告意外提示

- 7.15.3 应急管理
  - 应急管理计划和实践帮助组织解决灾难后的人员安全问题
  - 发生任何灾难时，人员安全应成为首要考虑因素

- 7.15.4 胁迫
  - 胁迫系统的一个例子是发送求救信号的按钮
  - 胁迫系统允许警卫针对紧急情况发出警报，并制定应急管理计划帮助组织应对灾难
  - 当人员单独工作时，胁迫系统非常有用
  - 如果胁迫系统意外启动，可以使用代码字向响应人员保证这是一次意外，或者省略键入实际响应的字词
